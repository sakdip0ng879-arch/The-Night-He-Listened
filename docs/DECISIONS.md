⚠ **สองแผ่นใช้กรอบพิกัดเดียวกันเป๊ะ** — สลับด้วยคลาส `plate-new` บน `#stage` เท่านั้น
ไม่มีพิกัดชุดที่สองเกิดขึ้นเลยแม้แต่จุดเดียว (กฎ 4 ยังอยู่ครบ)

**กฎ 1 — แยก Engine ออกจาก Data เด็ดขาด**
`js/` = engine เขียนครั้งเดียว แทบไม่แตะอีก · `data/` = เนื้อหา แก้ได้ถูก ๆ
แก้เนื้อเรื่อง 1 ฉาก = แก้ data 5 บรรทัด ไม่ใช่รื้อโค้ด

**กฎ 2 — สถานะแผนที่เก็บเป็น delta ไม่ใช่ snapshot**
แต่ละ beat บอกเฉพาะสิ่งที่ *เปลี่ยน* engine สะสมเอง
→ แก้ beat หนึ่งไม่กระทบ beat อื่น + แถบเวลาเลื่อนไป-กลับได้ฟรี

**กฎ 3 — ไฟล์ data เป็น `.js` ไม่ใช่ `.json`**
เปิดแบบ `file://` แล้ว `fetch()` จะโดน CORS บล็อก ใช้ `window.TK.xxx = {...}` แทน

**กฎ 4 — พิกัดเดียวทั้งโปรเจกต์**
ทุกพิกัดอ้างอิงพิกเซลของ `map.jpg` (1650×1950) **ห้ามมีระบบพิกัดที่สอง**

**กฎ 5 — ตารางชื่อกลาง**
`data/names.js` ผูก ไทย ↔ พินอิน ↔ ป้ายบนแผนที่ เขียนที่เดียว ใช้ทุกที่
ห้ามพิมพ์ชื่อสถานที่/บุคคลตรง ๆ ในไฟล์อื่น ให้อ้าง id เสมอ

**กฎ 6 — ป้ายจริง/แต่ง**
ทุก beat ต้องมี `fact: "real" | "fiction" | "mixed"` **เกณฑ์อยู่ที่ §8 ห้ามตัดสินด้วยความรู้สึก**

| | ภูมิประเทศภูเขา | ภูเขาที่มีชื่อ (4 จุด) |
|---|---|---|
| ชั้น | **แผ่นพื้น** (`reliefmask`) | ชั้นสัญลักษณ์ |
| รูป | **เส้นสัน + ขีดลาด + เงาลาดขวา** | สามเหลี่ยมทึบ + ป้ายชื่อ |
| หมึก | จาง (stroke .78 · เงา .16) | เข้ม |

**หน่วยที่ล็อก: เส้นสันเปิดปลาย 1 เส้น + ขีดลาดห้อย 2–3 ขีด + เงาอ่อนที่ลาดขวา**
(แสงจากซ้ายบน — คอนเวนชันแผนที่สากล · เจ้าของเคาะ 2026-09-02)

⚠⚠ **สามข้อห้ามที่ได้มาจากการลองผิดจริง (ดู BUGS_SEEN §E20)**
1. **ห้ามใช้รูปปิดที่มีฐาน** (สามเหลี่ยม/พหุเหลี่ยม) — พอเรียงกันฐานจะต่อกันเป็น
   **กำแพงทึบ** เสมอ ไม่ว่าจะทึบ กลวง ใส่เงา หรือทำให้บังกัน · เส้นเปิดปลายไม่มีฐาน
   จึงซ้อนกันได้ไม่รู้จบ — **นี่คือเหตุผลที่แผ่นของ William L ใช้เส้นเปิดปลายมาตลอด**
2. **ห้ามวาดภูมิประเทศทับ `d` ของ edge ถนน** — ช่องว่างระหว่างกลุ่มเขาคือหุบ
   (หุบเซีย · จื่ออู่ · ลั่ว มองเห็นเป็นทางโล่งในหมึกที่สกัดออกมา) ·
   **ตรวจได้ด้วยเครื่อง** เพราะมีทั้งกราฟถนนและ mask แล้ว
3. **ห้ามทดสอบสไตล์ด้วยเลย์เอาต์ที่ไม่มีหุบ** — อัดสันชนกันเต็มแถบแล้วลากถนนทับ

`G > R+22 && G > B+22 && G < 215` (ย่านฉินหลิ่ง 380×270 ได้ 4,349 พิกเซล = 4.24%)

## §4 · ★ เส้นทางเดินทัพ — กราฟถนน (ใหม่ทั้งหมด · แทนกฎเดิมทั้งกอง)

### สิ่งที่ถูกยกเลิก

| ยกเลิก | มาจาก | ทำไม |
|---|---|---|
| กฎ "ห้ามเส้นตรง" / คด ≥ 3% | P2 D11 | ตรวจ *รูปร่าง* ไม่ได้ตรวจ *เส้นทาง* เส้นที่โค้งสวยแล้วลอยข้ามภูเขาผ่านได้ |
| มาตรฐาน `flips` / `maxTurn ≤ 55°` | HANDOFF §2.13 | ปัญหาเดียวกัน แก้อาการไม่ได้แก้เหตุ |
| ตาราง `STRAIGHT_OK` | check_routes | เป็นการยกเว้นด้วยมือ ซึ่งแปลว่ากฎผิดตั้งแต่ต้น |
| ตาราง `SHAPE_OK` | check_routes | เหมือนกัน |
| flag `reverse` บน route | SCHEMA เดิม | กลับ array ก็ได้เส้นถอย ไม่ต้องมี flag |

**เหตุผลที่ทิ้งทั้งกอง:** กฎสี่ชั้นนี้แก้ปัญหาเดียวกันทั้งหมด และ HANDOFF §2.5 บันทึกอาการไว้เองแล้ว
ว่าคนเขียนจะเริ่ม *"ขยับจุดควบคุมจนตัวเลขผ่าน"* — **กฎที่ชวนให้โกงคือกฎที่ผิด**

### โครงใหม่ — สามชั้น

**ชั้น 1 · จุด (node)** ทุกที่ที่กองทัพหยุดหรือผ่านได้จริง — `data/roads.js`

```js
tianshui:   { type:"city",         xy:[356,607] },
jieting:    { type:"pass",         xy:[348,549], note:"คอขวดถนนเกวียนสายเดียว" },
jincheng:   { type:"ford",         xy:[292,468], river:"yellow" },
xiegu_kou:  { type:"valley_mouth", xy:[516,663] },
wuwei:      { type:"well",         xy:[248,392] },
```

ชนิด: `city` · `pass` · `ford` · `valley_mouth` · `well` · `junction`

**ชั้น 2 · ถนน (edge)** หนึ่งช่วง = ถนนจริงหนึ่งช่วง วาดครั้งเดียว ใช้ตลอดเรื่อง

```js
{ a:"tianshui", b:"jieting",  terrain:"ridge", li:180, wagons:true,
  d:"M 356,607 C …" },
{ a:"tianshui", b:"chencang", terrain:"gorge", li:220, wagons:false,
  note:"หุบเขาแม่น้ำ Wei — คนกับม้าจูงผ่านได้ เกวียนไม่ได้ (ต้นฉบับภาคหก)" },
```

`terrain`: `valley` · `ridge` · `plain` · `desert` · `gorge` · `ford` · `gallery` (ทางไม้เลียบผา)
· **`river`** (เพิ่ม 2026-09-01 · บทที่ 11) — เส้นทางเรือ · `wagons:false` เสมอ
  ยกเว้นกฎ "ห้ามลุยข้ามผืนน้ำ" แบบเดียวกับ `ford` **และมีกฎกลับด้านคู่กัน**:
  river ที่เปียกน้อยกว่าครึ่งเพดาน = เตือน เพราะแม่น้ำที่ลากถูกต้องเปียกเกือบทั้งเส้น
  (เจอกับตัวเองทันทีที่เพิ่มคำนี้ — `xiakou–wuchang` ลากด้วยตาแล้วได้ 0 หน่วย
  ทางแก้คือ **อ่าน `landmask` ตรง ๆ อย่าลากจากภาพครอป**)

**ชั้น 3 · การเดินทัพ** ประกาศเป็น **รายชื่อจุด** ไม่ใช่เส้น

```js
c3_02_zhangfei: {
  side:"han", commander:"Zhang Fei", troops:15000,
  path:["hanzhong","yangpingguan","wudu","xiabian"],
  year:221, season:"autumn"
}
```

engine ต่อ `d` ของแต่ละ edge เข้าด้วยกันแล้ววิ่งลูกศรตามนั้นด้วย `path.getPointAtLength()`

### กฎที่บังคับใช้ผ่านโครงสร้าง ไม่ใช่ผ่านตัวตรวจ

1. **เดินเมืองต่อเมือง จุดต่อจุด** — `path` คือรายชื่อจุด เป็นอย่างอื่นไม่ได้
2. **ต้องผ่านด่าน ห้ามอ้อม** — ด่านคือ node · ไม่มี edge ที่อ้อมมัน = อ้อมไม่ได้
3. **ห้ามข้ามแม่น้ำนอกท่า** — edge ที่ข้ามน้ำมีเฉพาะที่ปลายเป็น `type:"ford"`
4. **ห้ามโค้งทะลุภูเขา** — edge มีเฉพาะที่ถนนมีจริง
5. **เส้นทางเดียวกันต้องหน้าตาเหมือนกันเสมอ** — เพราะมันคือ edge อันเดียวกัน
   (นี่คือ *"เลือกสัก standard"* ที่เจ้าของขอไว้ในโปรเจกต์ 2 — ตอนนี้บังคับโดยโครงสร้าง)

### กฎที่ยังต้องตรวจด้วย `check_routes.js` (เขียนใหม่)

| ตรวจ | เกณฑ์ |
|---|---|
| edge มีจริง | ทุกคู่ที่ติดกันใน `path` ต้องมี edge · ไม่มี = **error** |
| หัวท้ายต่อกัน | จุดสุดท้ายของ edge หนึ่ง = จุดแรกของ edge ถัดไป |
| **ของใครยกไปเท่าไหร่** | `side` + `troops` **ต้องมีทุกเส้นที่มีการรบ** · ไม่มี = build ไม่ผ่าน |
| อยู่บนบก | ทุก node ต้องอยู่บนบกตาม `landmask.js` (ยกเว้น `ford`) |
| เกวียนผ่านได้ | ถ้าเส้นนั้นมีขบวนเสบียง ทุก edge ต้อง `wagons:true` |
| **★ ความเร็วเดินทัพ** (ข้อ 13 · เขียนโค้ดจริง 2026-09-02) | Σ `li` ÷ `days` ของ march · เกิน **100 ลี้/วัน** = ⚠ เตือน เว้นแต่ประกาศ `forced:"เหตุผล + ¶"` (ขบวนเสบียง `supply:true` เพดาน 40 — ยังไม่มีเส้นไหนปลุก **ให้เจ้าของเคาะตัวเลขก่อนวันที่มันฟ้องครั้งแรก**) · **ด้านกลับ**: ต่ำกว่า 10 ลี้/วัน = รายการทบทวน เพราะเกือบทุกครั้งแปลว่า `days` ที่ใส่มาเป็นเวลาของ *การทัพ* ไม่ใช่เวลาเดินทาง · ⚠ `days` มาจากต้นฉบับเท่านั้น ไม่ใช่จากการเดา — **ไม่แน่ใจให้ใส่น้อยกว่าจริง** (ความเร็วสูงกว่าจริง = ด้านที่ปลอดภัยของกฎเพดาน) |
| **★ ท่อนที่พาทัพถอย** (ข้อ 12 · เพิ่ม 2026-08-27) | ฉายเวกเตอร์แต่ละท่อนลงบนทิศ `ต้นทาง → ปลายทาง` · ท่อนที่ได้ค่า**ติดลบ**เกิน 8% ของระยะต้น-ปลาย และเกิน 4 หน่วย = ลูกศรชี้สวนทางการทัพ · **ยกโทษเมื่อ edge ของท่อนนั้นเองมี `note`** (ไม่ใช่ note ของเพื่อนบ้าน ไม่ใช่ note ของ march — สองอย่างนั้นยกโทษให้ทุกเส้น) · ⚠ **ห้ามกลับไปใช้ detour ratio หรือมุมหัก** ลองแล้วมันฟ้องถนนที่ถูกต้องเกือบทุกเส้น เพราะภูเขาบังคับให้ถนน*หัก*เป็นเรื่องปกติ สิ่งที่ไม่ปกติคือถนน*ถอย* |

**ข้อยกเว้นเรื่องป้ายกำกับ:** ถ้าต้นฉบับเล่าแค่ว่า "เดินไปตรงนั้น" โดยไม่มีการรบ
ไม่ต้องใส่ `troops` ได้ — ดูตามความเหมาะสม **แต่ `side` ต้องมีเสมอ**

### ★★ วิธีลาก `d` ที่เป็นน้ำ — ห้ามลากด้วยตา (ล็อก 2026-09-01 · เจ้าของทัก)

> *"เส้นทางดูไม่ตามแม่น้ำ และมีการใช้เส้นตรงมาก ยิ่งที่เจียนเย่ มันตรงเข้าไปได้เลยเหรอ"*

**`node tools/trace_river.js <a> <b> [--land]`** — Dijkstra บนกริดของ `landmask.js`
(ช่องน้ำถูก ช่องบกแพง · `--land` กลับค่าเพื่อหาถนนที่เลี่ยงน้ำ) แล้วมนมุมด้วย Q
· `--all` เทียบเส้นที่วาดไว้ทุกเส้นกับร่องน้ำจริง

**ทำไมถึงเป็นกฎ ไม่ใช่คำแนะนำ:** ลากด้วยตาจากภาพครอปแล้ววัดย้อนหลัง ได้แม่น้ำที่
เปียกแค่ 16–38% และมีช่วงแห้งติดกันถึง 250 หน่วย · **มันดูถูกต้องบนจอทุกเส้น**
ความผิดมองไม่ออกจากภาพ แต่วัดออกได้ทันที (BUGS_SEEN §E16)

⚠ **วัดความเปียกจากเส้นที่มนมุมแล้ว ไม่ใช่เส้นดิบ** — การมนมุมตัดโค้ง เส้นอาจหลุด
ร่องน้ำ ถ้าวัดจากเส้นดิบจะได้ตัวเลขสวยกว่าของจริง

### ถ้าเรื่องต้องการเส้นที่ไม่มีในกราฟ

**เพิ่ม edge พร้อมเหตุผลทางภูมิศาสตร์ในช่อง `note`** — ซึ่งคือการตัดสินใจที่มองเห็น
ไม่ใช่การเผลอ · **ห้ามลาก `path` ข้าม node ที่ไม่มี edge เชื่อม เพื่อให้ภาพสวย**

### ★ การประกอบเส้นบนจอ (ล็อกเป็นบรรทัดฐาน 2026-08-25 — เจ้าของสั่ง "เอาเป็นบรรทัดฐานเลย")

builder ใน `roads.js` ประกอบการเดินทัพแบบ **"สุ่มจุดแล้วลบมุม"** — ห้ามกลับไปต่อสตริง path:

1. สุ่มจุดตาม `d` ของทุก edge ด้วยคณิตล้วน (M·L·C·Q · ก้าว 7 หน่วย) — ทำงานเหมือนกัน
   ทั้งเบราว์เซอร์และ node · เดินสวนทาง = กลับลำดับ array จบ (ไม่มี reverseD อีกแล้ว)
2. **ลบมุมที่รอยต่อ node ด้วยโค้ง Q รัศมี `R_JUNC = 12` หน่วย** (หดเองเมื่อรอยต่อชิดกัน)
   — นี่คือสิ่งที่แก้ "เส้นหักศอก" ที่ประตูคู่ Baishui–Yangping · โค้งภายใน edge
   ที่ลากมือไม่ถูกแตะ · ปลายเส้นต้องตรงจุด node เป๊ะ (`test_roads` วัด < 2px)
3. **edge ที่ยังไม่ได้ลาก `d` = เส้นตรงต่อจุด** (เจ้าของเคาะ) — ห้ามโก่งเลียนแบบถนน
   ภาพจึงบอกสถานะงานไปในตัว: **ตรง = ยังไม่ลากตามภูมิประเทศ (งานค้างของ check_routes) ·
   โค้ง = ลากจริงแล้ว** เช่นช่วงช่องเขา Jianmen ที่โค้งตามหุบเขา
   ★ **แต่ edge ที่การเดินทัพของฉากใช้จริง ต้องลาก `d` ก่อนปิดบทนั้น** (เจ้าของทัก
   2026-08-26 — เส้นตรงของ march หม่าเชาอ่านเป็น "ส่งสาส์น" ขณะที่เส้นอื่นเดินตามภูมิประเทศ)
   placeholder ตรงมีไว้สำหรับ edge ที่วางล่วงหน้าแต่ยังไม่มีฉากไหนเหยียบเท่านั้น
4. แก้ builder แล้วต้องรัน `tools/test_roads.html` ผ่าน http — และจำ BUGS_SEEN §E8:
   หน้านั้น**ต้องมีแถวผลลัพธ์** ไม่มีแถว = ตัวเทสต์ตายเอง ไม่ใช่ของสะอาด

> ⚠ ยิ่งกล้องแคบ ยิ่งไม่มีหมุดหลุด — ตัวตรวจรุ่นเก่าจึงเงียบสนิทในเคสที่แย่ที่สุด
> `check_camera` ตรวจ `TIGHT = 520` แล้ว

## §6 · ลูกศรต้องออกจากที่ที่ฝ่ายนั้นอยู่จริง (ล็อก — จาก P2 D12)

ทุกลูกศร: หาจุดตั้งต้น → ดูว่าตกในเขตไหน → เขตนั้นเป็นของใคร ณ ฉากนั้น
ถ้าไม่ใช่ฝ่ายเดียวกับลูกศร และไม่ใช่ `none` → **error** (`check_map.js` ข้อ 5)

ยกเว้น **สามกรณีรายลูกศร** ที่ลดเป็น warning เพราะถูกต้องได้จริง
(★ แก้ 2026-08-27 — ของเดิมข้อแรกเป็นเงื่อนไข**รายฉาก** คือ "ฉากนี้มี clash ที่ไหนก็ได้"
ซึ่งหลวมจนลูกศรสามพันของ c7-11 ที่ออกตัวกลางดินวุ่ยรอดไปได้ เพราะศึกที่ยกมาอ้าง
อยู่ห่างออกไป 100 หน่วยและเป็นคนละเรื่องกันสิ้นเชิง):
- **มี clash ห่างจาก *ปลายลูกศรอันนี้* ไม่เกิน 45 หน่วย** — ทัพที่ล้อมเมืองยืนบนดินข้าศึกได้
  ก็ต่อเมื่อสิ่งที่มันล้อมคือสิ่งที่มันชี้ไปหา (45 = ระยะที่ §7 บอกว่าวงปะทะสองวงเริ่มพันกัน)
- **`retreat:true`** — การถอยย่อมเริ่มจากที่ที่เพิ่งรบมา
- **จุดออกตัวทับเส้นทางของลูกศรฝ่ายเดียวกันอีกอันในฉากเดียวกัน** — กองแยกที่ผ่าออกจาก
  ขบวนซึ่งฉากนี้วาดไว้แล้ว · ★ กองแยกแบบนี้ **ต้องมีหมุดที่จุดแยกด้วย** ไม่งั้นบนจอ
  ลูกศรจะงอกขึ้นจากพิกัดเปล่า (เจ้าของทัก c7-11: *"มีทัพแยกเริ่มจากของเว้ยเหยียนเฉยเลย"*)

**และห้ามแก้ปัญหา "การวาด" ด้วยการทำให้ "ข้อมูล" โกหก** — รูปทับกันไม่เป็นปัญหา
เจ้าของบอกไว้เองว่า *"มันมีการย้ำตรงนั้นอยู่แล้ว คนอ่านเห็นแล้วเข้าใจทันที"*

## §7 · หมุด (ล็อก — จาก P2 D13)

| `side` | หมุดหมายถึง | หน้าตา |
|---|---|---|
| ไม่ใส่ | "ฉากนี้ชี้ให้ดูตรงนี้" | จุดทอง + คำบรรยายทอง (`mk-cap`) |
| ใส่ | "ที่นี่เป็นของฝ่ายนี้" | จุดสีฝ่าย + ป้ายติดจุดสีฝ่าย (`mk-chip`) |

**⚠ หมุดที่มีสีไม่ได้เปลี่ยนเจ้าของพื้นที่** สีของแผ่นดินมาจาก `mapDelta` อย่างเดียว
· วงปะทะสองอันที่ห่างกันน้อยกว่า ~40 หน่วย จะพันกันเป็นก้อนเดียว
· `clash` + `mapDelta` ของเมืองเดียวกัน ในฉากเดียวกัน = ผิด SCHEMA

### ★★ ธงพลิกตอนทัพเดินถึง ไม่ใช่ตอนเข้าฉาก (ล็อก 2026-08-28 · เจ้าของสั่ง)

> *"ครั้งเดียวที่เขาเกือบสำเร็จ กับ สี่สิบวันแล้วก็ไม่มีความหมาย —
>  ให้เปลี่ยนสีเทียนสุ่ยตอนที่ทัพเดินไปถึงจะดีกว่า"*

กฎ §7 ข้างบน (*หมุดสีเล่าล่วงหน้าไม่ได้*) เป็นกฎบน **แกนฉาก** · ข้อนี้คือกฎเดียวกัน
บน **แกนวินาที** — ของเดิม `setOwners` ถูกเรียกที่บรรทัดแรกของ `render()` แผ่นดินจึงพลิกสี
ที่ t=0 แล้วลูกศรค่อยใช้เวลาอีก 1–3 วินาทีเดินไปหาเมืองที่เปลี่ยนมือไปเรียบร้อยแล้ว
= **ผลมาก่อนเหตุ ทุกฉากที่มีทั้ง delta และการเดินทัพ** (14 ฉากทั้งเล่ม)

| ฉากแบบไหน | พฤติกรรม |
|---|---|
| มี `mapDelta` **และ** มีลูกศรในฉาก | พักการทาสีไว้ · ลูกศรเส้นสุดท้าย settle แล้วจึงพลิก |
| มี `mapDelta` ไม่มีลูกศร (เมืองยอม · ธงเปลี่ยนด้วยเอกสาร) | พลิกทันทีเหมือนเดิม — ไม่มีอะไรให้รอ |
| `scrub` (ลากแถบเวลา) · `init` · `shot.ps1` | พลิกทันที — ไม่มีแอนิเมชันให้รอ และการหน่วงคือความหน่วงเปล่า |

กลไก: `setOwners(owners, hold)` เก็บเขตที่ถูกพักไว้ใน `ownerHold` · `setMarkers` นับลูกศร
ที่กำลังจะวิ่ง (`walking`) แล้วเรียก `flushOwners()` ใน `settle()` ของเส้นสุดท้าย ·
ฝั่ง `ui.js` คำนวณ `hold` จาก `b.mapDelta` เอง **ไม่มีฟิลด์ใหม่ในไฟล์ฉาก** — กฎเดียว
ใช้ได้ทั้งเล่มโดยไม่ต้องประกาศอะไรต่อฉาก

⚠ **ตัวตรวจทุกตัวเป็น static จึงไม่มีทางเห็นข้อนี้** และไม่มีทางเห็นข้ออื่นในตระกูลเดียวกัน
(ลำดับเวลาในฉากเดียว) · ตรวจได้ทางเดียวคือเปิดของจริงแล้วดู — ⚠ แท็บที่ไม่ได้อยู่หน้าจอ
มี `visibilityState:"hidden"` ซึ่งหยุด `requestAnimationFrame` ทั้งหมด **tween จะไม่มีวัน
เดินจบ** ถ้าจะทดสอบด้วยสคริปต์ ต้องสลับ `TK.engine.tween` เป็นตัวที่กระโดดไปจุดจบทันที
(คืนค่าเป็น *ฟังก์ชัน* ยกเลิก ไม่ใช่ออบเจกต์ — `flyTo` เรียก `camCancel()` ตรง ๆ)

## §8 · เกณฑ์ป้ายจริง/แต่ง (ล็อก)

| ป้าย | เกณฑ์ |
|---|---|
| `real` | เหตุการณ์ในฉากมีบันทึก และเล่า **ตรงที่ ตรงปี ตรงธง ตรงผล** |
| `mixed` | มีบันทึก แต่ถูก **ย้ายที่ · ย้ายปี · ย้ายธง · เปลี่ยนผล** หรือมีของจริงกับของแต่งปนกัน |
| `fiction` | ไม่มีบันทึก ไม่ว่าจะวางบนนิสัยจริงของตัวละครแค่ไหนก็ตาม |

**"โลกรอบตัวต่างไป" ไม่นับ** — ถ้าฉากหลังนับด้วย ทุก beat หลังจุดแยกจะเป็น `mixed` หมด
แล้วป้าย `real` ก็ไม่เหลือความหมาย

**สองข้อยกเว้น**
1. เหตุการณ์จริงในอดีตที่ฉากยกมาอ้างประกอบ นับเป็นของจริงในฉาก
2. บทสนทนาที่แต่งให้ตัวจริงในเหตุการณ์จริง ไม่ทำให้ฉากเป็น `fiction` — นับที่เหตุการณ์ ไม่ใช่ที่คำพูด

**ที่มาของคำตอบทั้งหมดอยู่ในภาคผนวกของต้นฉบับ** ซึ่งรอบนี้เขียนแยกสามส่วนแล้ว
(ของจริง · ของแต่ง · หมายเหตุภูมิศาสตร์ที่ต้องย้ายสองจุด) — ฉากที่แตะสองจุดนั้นเป็น `mixed` เสมอ

## §9 · ประชากรกับกำลังพล (ล็อก)

### สูตร

```
กำลังพล(ฝ่าย) = Σ กำลังที่แผ่นดินที่ถืออยู่เลี้ยงได้      ← geo.js weights
              × digest(อายุการยึด)                        ← ★ ยึดได้ ≠ เกณฑ์ได้ทันที
              × (1 + 0.5 × สัดส่วนแผ่นดินเดิมที่เสียไป)   ← ถูกบีบก็เกณฑ์หนักขึ้น
              + Σ evac(อายุ) ของแผ่นดินที่เพิ่งเสีย        ← ★ ทัพที่ถอนออกมา ยังต้องเลี้ยง
              − Σ losses × 0.68^(ปีที่ผ่านไป)             ← เสียแล้วเกณฑ์คืนได้
```

```
DIGEST = [0, 0.25, 0.50, 0.75]     ผู้ยึด · อายุ 0–3 ปี · ตั้งแต่ปีที่ 4 = เต็ม
EVAC   = [0.60, 0.40, 0.25, 0.10]  ผู้เสีย · ทัพที่ถอนออกมาและยังไม่ถูกทดแทน
```

**★ `digest`/`evac` ยกมาจาก `engine.js` ของโปรเจกต์ 2 และโปรเจกต์นี้ขาดไม่ได้**
เพราะปี 262 ฮั่นกลืนแผ่นดินเหนือ 4.4 ล้านคนในปีเดียว ถ้าไม่มีการหน่วง กำลังพลจะกระโดด
สามเท่าในเฟรมเดียว ซึ่งคือ landslide ที่เจ้าของเคยทักในโปรเจกต์ 2
**⚠ ประชากรไม่ถูกหน่วง มีแต่กำลังพล** คนอยู่ที่เดิม สิ่งที่ยังไม่มาคือความสามารถในการเก็บภาษี

### ตัวเลขตั้งต้นของโปรเจกต์นี้ (เคาะแล้ว · ต่างจากสองโปรเจกต์ก่อน)

|---|---|---|

| ฮั่น ปี 226 | **~1.5 ล้าน** | + Longyou + Hexi · ต้นฉบับภาคห้า |
| เหนือที่ได้มาปี 262 | **+4.4 ล้าน** | ต้นฉบับภาคสิบเอ็ด |
| ม้า ปี 225 | **40,000 ตัว** = ทหารม้า **18,000 คน** | ต้นฉบับภาคสาม (2–3 ตัว/คน) |
| ทหารม้า Beiyuan 233 | **20,000 คน** | ต้นฉบับภาคเจ็ด |

⚠ **ฮั่นในเอกภพนี้ไม่เสียกองทัพที่ Yiling** ยอดตั้งต้นปี 222 จึงสูงกว่าทุกโปรเจกต์ก่อน

### กฎ

**ตัวเลขกองทัพที่เขียนในเนื้อเรื่อง ต้องไม่เกินกำลังพลที่ฝ่ายนั้นมีในฉากนั้น**
`tools/check_hud.js` เก็บไว้ในตาราง `CLAIMS` — เพิ่มฉากที่เอ่ยจำนวนทัพเมื่อไหร่ ต้องเพิ่มลงตารางด้วย

**เลขบนป้ายต้องลดตามที่เสียไปจริง** · **หลอดวัดกับตัวเลขข้างหลอดต้องวัดสิ่งเดียวกัน**
(เคยพลาด: หลอดวัดจำนวนเขต ตัวเลขเป็นทหาร — วุ่ยมีทหารน้อยสุดแต่หลอดยาวสุด)

### ★★ การเสียกำลังพลมีสองชนิด · ปัดที่หลักพัน (เพิ่ม 2026-08-27)

เจ้าของทัก *"การขึ้นลงกำลังพล มันไม่เคยขยับเลยจริงๆ"* — ไล่ดูแล้วเจอสองเรื่องคนละชั้น

**① การปัดเศษกลืนการเคลื่อนไหวทิ้ง** — `strength()` ปิดท้ายด้วย `Math.round(troops)` ซึ่ง
ปัดที่**หน่วยหมื่น** ค่าจริงของวุ่ยที่เดิน 43.12 → 42.69 → 42.33 → 41.49 (ขยับทุกปี)
จึงถูกบีบให้อ่านเป็น 430,000 → 430,000 → 420,000 → 410,000 แล้วค้างที่ 410,000 อยู่เจ็ดปี
→ **ปัดที่หลักพัน** (`Math.round(t*10)/10`) · แสดงผลเป็น `431k` ไม่ใช่ `431,000`
⚠ ตัวตรวจต้องเดินสูตรเดียวกับ engine ทุกบรรทัด — `check_hud` มีสำเนาสูตรอยู่ แก้พร้อมกันเสมอ

**② `losses` ไม่ครอบคลุมกองที่ยอมจำนน** — บทที่ 7 มีทหารวุ่ยยอมจำนน **32,500** ซึ่ง
*มากกว่า*คนที่ตายในสนามรบทั้งเล่มรวมกัน แต่มันหายไปในคอมเมนต์บัญชีทัพ ไม่เคยแตะ HUD

| ฟิลด์ | หมายถึง | ฟื้นคืนไหม |
|---|---|---|
| `losses` | ตายในสนาม | **ใช่** — รัฐเกณฑ์คนใหม่มาแทน (`RECOVER` 0.68/ปี) |
| `taken` | ยอมจำนน / ถูกกลืน | **ไม่** — คนที่ยกธงขาวแล้วเดินกลับบ้านซึ่งเป็นแผ่นดินของอีกฝ่าย เกณฑ์กลับมาไม่ได้ |

- หน่วยเป็น**หมื่น**ทั้งคู่ · `taken` **ไม่โอนให้ผู้ชนะ** — แผ่นดินที่ยึดได้ต่างหากที่เลี้ยงทหารให้
  ซึ่ง `digest` หน่วงไว้อยู่แล้ว การโอนตรงจะเป็นการนับซ้ำ
- **ฉากที่มี `taken` ต้องมีหมุดของฝ่ายที่เสียคน ที่มี `strength` อยู่ในฉากเดียวกัน**
  (`build_timeline` บังคับ) — ตัวเลขบน HUD จะลดลงโดยไม่มีอะไรบนจออธิบายไม่ได้
- ⚠ **ง่อยืนนิ่งทั้งเล่มถูกแล้ว** ในเอกภพนี้ง่อไม่ได้รบเลยหลังราชโองการเติ้งจือ
  อย่าไปแต่งตัวเลขให้มันขยับเพื่อความสวยงามของหลอด

### ★★ `front` — กำลังรบแนวตะวันตก (ทางเลือก ก · เจ้าของเคาะ 2026-08-27)

เรื่องนี้มีตัวเลขสามชั้น และก่อนหน้านี้คนอ่านเห็นแค่สองชั้น:

```
ชาติ (แถบ HUD ~400k ทุกแนวรบ) ⊃ แนวตะวันตก (~95k) ⊃ กองปฏิบัติการ (ลูกศร 12k–40k)
```

ชั้นกลางมีอยู่แต่ในร้อยแก้วกับคอมเมนต์บัญชีทัพ — คนอ่านจึงเห็นวุ่ย "นับแสน" แล้วเห็นฉากรบ
ที่มีไม่กี่หมื่น แล้วสรุปว่าตัวเลขมั่ว · `front: { han, wei }` หน่วยหมื่น เป็นตัวเลขชั้นกลางนั้น

**ทำไมประกาศ ไม่ใช่คำนวณ (วัดแล้ว):** สิบเขตตะวันตกรวมกันเกณฑ์ได้ **70,000** แต่กองทัพ
ที่ยืนอยู่ตรงนั้นปี 232 รวม **180,000** เพราะทั้งสองฝ่ายขนทัพมาจากนอกแนว · โมเดลเขตตอบ
*"แผ่นดินนี้เลี้ยงทหารได้เท่าไร"* ซึ่งไม่ใช่คำถามเดียวกับ *"ตอนนี้มีทหารยืนอยู่ตรงนั้นเท่าไร"*
บิดให้ตอบคำถามที่สองได้ แต่มันจะตอบคำถามแรกผิดทั้งเล่ม

**⚠⚠ มันคือ "แหล่งความจริงที่สอง" ที่ §14 ห้าม — ราคาที่ต้องจ่ายเพื่อให้มันอยู่ได้:**
`check_hud` **ข้อ 9** หนีบมันไว้ระหว่างสองชั้นที่คำนวณจากของจริง **ทุกฉาก**

| ตรวจ | เกณฑ์ |
|---|---|
| ชั้นบน | `front[side] ≤ กำลังทั้งรัฐของ side` — แนวรบใหญ่กว่าประเทศไม่ได้ |
| ชั้นล่าง | ทุก `strength` บนหมุด/ลูกศรของ side ในฉากนั้น `≤ front[side]` — กองเดียวใหญ่กว่าแนวรบไม่ได้ |
| ส่วนต่าง | พิมพ์ delta เทียบ `losses`+`taken` ที่บันทึกจริงทุกครั้งที่ประกาศ |

- ไม่ประกาศ = **สืบค่าจากฉากก่อนหน้า** ประกาศเฉพาะตอนมันเปลี่ยน · ก่อน c6-03 ไม่มีค่า
  = ไม่แสดงบรรทัด ซึ่งถูก (แนวรบตะวันตกยังไม่เป็นของจริงจนกว่าทั้งสองฝ่ายจะมีทัพยืนประจำ)
- `front` **ตกได้จากสามเหตุ** — ตายในสนาม (`losses`) · ยอมจำนน (`taken`) ·
  **ย้ายออกจากแนวรบ** (ยังอยู่ในกองทัพชาติ) · เหตุที่สามถูกต้องและไม่ใช่ losses ตัวตรวจ
  จึงไม่ฟ้องเป็น error **แต่พิมพ์ออกมาเสมอ** — บัญชีทัพจะดริฟต์ออกจากฉากเงียบ ๆ ไม่ได้อีก

**★★ `front` ขึ้น = ต้องมีเส้นบนกระดาน (เคาะ 2026-08-27 · เจ้าของทัก c8-05)**
> *"จู่ ๆ เว่ยมีทหารพุ่งมาสามหมื่น ไม่มีเส้นว่ามาจากตรงไหน ส่งมาจากนครหลวงไหม"*

`front` **ตกได้**โดยไม่มีลูกศร (ตายในสนามมี clash อธิบายอยู่แล้ว · ย้ายออกคือการหายไป
ซึ่งไม่ต้องวาด) แต่ `front` **ขึ้นไม่ได้**โดยไม่มีลูกศร เพราะกำลังที่เพิ่มขึ้นต้อง
*เดินมาจากที่ไหนสักแห่ง* และที่แห่งนั้นคือข้อมูลของเรื่อง ไม่ใช่รายละเอียดทางบัญชี —
c8-05 ร่างแรกขึ้น 65k→90k ด้วยหมุดกับร้อยแก้วอย่างเดียว คนอ่านจึงเห็นวุ่ยงอกทหาร
สองหมื่นห้าจากอากาศ และเดาว่ามาจากนครหลวง ทั้งที่ประเด็นทั้งฉากคือ **มันไม่ได้มาจาก
นครหลวง** มันมาจากชายแดนเหนือที่เลิกเป็นชายแดนตั้งแต่ c8-01

| ต้องมี | รายละเอียด |
|---|---|
| ลูกศรจริง | มี `route` ในกราฟถนน · ต้นทางคือที่ที่กองนั้นยืนอยู่จริงก่อนหน้า |
| เลขบนเส้น | `strength` **และ** `who`/`name` — ไม่มีชื่อผู้ถือ = ใส่ `name` (กองไม่มีชื่อในต้นฉบับ) เพราะ engine วาดชิปเมื่อมีชื่อเท่านั้น **เลขที่ไม่มีชิปเท่ากับไม่มีเลข** |
| ยอดตรงกัน | Σ `strength` ของลูกศรที่เข้าแนว = delta ของ `front` เป๊ะ (c8-05: 65+25 = 90) |

⚠ นี่คือโรคเดียวกับกอง 8,500 ของ c7-11 และกอง 20k ที่ c7-10 — ครั้งนี้เป็นกฎแล้ว

**ฉากที่มีสมรภูมิ ห้ามเขียน `losses` เอง** `build_timeline.js` คิดให้จากไฟล์ศึกโดยตรง
· ขบวนเสบียงรูปประทุนเกวียนไม่นับ เพราะเป็นวัวต่างไม่ใช่ทหาร
· ฉากที่เล่าด้วยคำบรรยายล้วน เขียน `losses` เองได้

## §10 · เวลา · ฤดู · ลำดับ (ล็อก)

**ลำดับใน array = ปฏิทิน เสมอ** id คงเดิม เปลี่ยนแค่ตำแหน่ง
ต้นฉบับเล่าตาม *ลำดับเรื่อง* ไม่ใช่ *ลำดับเวลา* — เจอมาแล้วสามครั้งในโปรเจกต์ 2

**⚠ เรื่องนี้จงใจให้ภาคสามกับภาคสี่ซ้อนเวลากัน (224–225 ทั้งคู่)** ภาคสามเล่าฝั่งฮั่น
ภาคสี่เล่าปีเดียวกันจากฝั่งวุ่ย · **beat ยังเรียงตามปฏิทินเหมือนเดิมไม่ว่ามาจากภาคไหน**
เก็บภาคต้นทางไว้ในช่อง `part` เพื่ออ้างอิง ไม่ใช่เพื่อเรียงลำดับ

**ฤดู** — `season` เป็น optional ระบุเฉพาะที่ต้นฉบับระบุ การเติมให้ครบทุกฉากคือการกุ
เดือนจันทรคติ **1–3 = 春 · 4–6 = 夏 · 7–9 = 秋 · 10–12 = 冬**

**ย้ายลำดับ beat แล้วต้องย้าย "สถานที่" ตามไปด้วย** — กล้องกับหมุดผูกกับลำดับ ไม่ใช่กับ id

### §10.1 · ★★ `wave` บนลูกศร — ลำดับ *ภายใน* หนึ่งฉาก (เพิ่ม 2026-09-01)

กติกา "หนึ่งเฟรมไม่มีเวลา" ยังอยู่ครบ — แต่ **ลำดับการวาดมีเวลา** และในฉากที่เหตุกับผล
อยู่ในเฟรมเดียวกัน มันเป็นสิ่งเดียวที่บอกได้ว่าอะไรเกิดก่อน

ที่มา: c10-08 วาดกำลังเสริมวุ่ย 25k กับลูกศรถอยของง่อ 3k พร้อมกัน · ความเร็วลูกศร
คิดจาก **ความยาวบนจอ** (§3) เส้นถอยซึ่งสั้นกว่ามากจึงลงจอดก่อนเสมอ — บนจออ่านว่า
*"ง่อถอยก่อนกำลังเสริมจะมาถึง"* ซึ่งกลับหัวกลับหางกับเรื่อง (เจ้าของทัก 2026-09-01)

| ค่า | ความหมาย |
|---|---|
| ไม่ใส่ / `wave:0` | ออกพร้อมกันเหลื่อม 140ms ต่อ marker — **พฤติกรรมเดิมทุกประการ** |
| `wave:1, 2, …` | ไม่ออกจนกว่า**ทุกเส้นในคลื่นก่อนหน้าจะถึงที่หมาย** + 240ms |

กฎการใช้:
1. **ต้องเรียง marker ตามคลื่นในอาร์เรย์ด้วย** — ตัวนับคลื่นเดินหน้าอย่างเดียว
   (ประตูเปิดตอนเจอ `wave` ที่สูงกว่าค่าปัจจุบัน แล้วปิดตายไม่ย้อนกลับ)
2. **ธงยังพลิกตอนเส้นสุดท้ายถึงที่หมายเหมือนเดิม** (§7 · `flushOwners`) — คลื่นไม่ได้
   เปลี่ยนกลไกนั้น มันแค่ทำให้ "เส้นสุดท้าย" เป็นเส้นที่เรื่องบอกว่าควรเป็นเส้นสุดท้าย
3. **ห้ามใช้แทนการแตกฉาก** — คลื่นมีไว้เรียงเหตุ-ผลที่อยู่ในเฟรมเดียวกันอยู่แล้ว
   ไม่ใช่เครื่องมือยัดสองเหตุการณ์คนละเวลาเข้าเฟรมเดียว (กฎ §12 ขั้น 1.6 มาก่อนเสมอ)

ใช้แล้วสองที่: **c10-08** (25k ถึง → ง่อจึงถอย) · **c10-09** (ทัพกลางถอยไปสวี่ชาง →
เจียงเหวยจึงเดินเข้าลั่วหยาง → ธงจึงพลิก)

**★★★ คำตอบของ "จะแก้ไม่รู้จบไหม" คือ ทำให้มันเป็นตัวเลขที่นับได้ก่อน**

⚠ **อย่าเชื่อตัวเลข "น่าสงสัย" แบบหลวม ๆ** — ตอนแรกผมนับด้วยเกณฑ์ "ปลายห้อยที่มีหมึกอยู่ใกล้"

1. **สะพานโค้ง ไม่ใช่ท่อนตรง** — Bezier ที่ออกจากปลายตามทิศของลำน้ำทั้งสองข้าง
2. **วนซ้ำ** — ป้ายใหญ่ตัดลำน้ำเป็นสามสี่ท่อน ต้องเย็บทีละช่องจนหมด
3. **สะพานแบบบรรจบกลางลำ** — สาขาที่ไหลมาชนสายหลักตรงที่มีป้ายพาด ไม่มี "ปลายคู่" ให้จับ

⚠⚠ **ทางที่ลองแล้วไม่ได้ผล — อย่าลองซ้ำ** (จดไว้ในหัว `build_plate_water.js` ด้วย)

> ★ ลายเซ็นที่ชี้ขาดคือ **กล่องเล็ก + กลวง + มีตัวหนังสือดำอยู่ข้างใน**

> ⚠ และตัวตรวจต้อง**ยกเว้นปากแม่น้ำ** ด้วย ไม่งั้นทุกปากที่ไหลลงทะเลจะโดนฟ้องตลอดกาล

## §16 · ★ การเติมสีพื้นที่ — เส้นขอบร่วม (ล็อก 2026-08-25 · เจ้าของทัก "สีไม่คม ไม่ seamless")

**พรมแดนระหว่างเขตสองเขต เป็นเส้นเดียวกันเป๊ะทั้งสองฝั่งเสมอ** — `build_geo.js`
หั่นเส้นขอบเป็น **arc ตามคู่เพื่อนบ้าน** แล้วลดจุด/ลบมุม **ครั้งเดียวต่อ arc**
(ปลาย arc ตรึงที่จุดสามแยก) ก่อนประกอบรูปแต่ละเขตกลับจาก arc ชุดเดียวกัน

| กติกา | เพราะ |
|---|---|
| ห้ามลดจุดเส้นขอบ "เขตใครเขตมัน" | พรมแดนสองฝั่งจะเหลื่อมกัน เกิดเสี้ยวขาวรั่วระหว่างเขต |
| `.region` ใน CSS ใช้ stroke **1.5** เท่านั้น | มีหน้าที่เดียวคือกัน anti-alias · **ห้ามเพิ่มเพื่อกลบรอยขาว** — เห็นรอยขาวเมื่อไหร่แปลว่า build_geo พัง ไปแก้ที่ต้นเหตุ (ประวัติ: 34 → 10 → 1.5 สองค่าแรกคือยาแก้ปวดของโครงเก่า) |
| `build_geo` ต้องรายงาน "arc ถูก reuse ครบ" | จำนวน reuse = จำนวนพรมแดนใน · ถ้าเป็น 0 แปลว่ากุญแจจับคู่พัง แล้วรอยรั่วจะกลับมาเงียบ ๆ |
| แก้รูปใน geo.js แล้วต้องรัน `node tools\build_geo.js` | เหมือนเดิม — geo_fill.js เป็นไฟล์ generate ห้ามแก้มือ |

ผลพลอยได้ที่เจตนา: **`TK.regionArcs`** — ทุก arc รู้ว่าสองฝั่งคือเขตไหน (`b:null` = ชายฝั่ง/นอกเขต)

## §17 · ★ วงเส้นประ — กรอบเน้นพื้นที่ (ล็อก 2026-08-25 · เจ้าของสั่งทำเป็นบรรทัดฐาน)

**หน้าที่ (มีสองอย่างเท่านั้น):** (ก) เน้น **เขตพื้นที่ที่ฉากกำลังพูดถึง** ·
(ข) เน้น **พื้นที่ที่สนใจของยุทธการณ์นั้น** = กลุ่มเขตที่เป็นเวทีของแคมเปญ
ห้ามใช้บอกอย่างอื่น — เจ้าของพื้นที่คือ *สีระบาย* · จุดเกิดเหตุคือ *หมุด/วงปะทะ* ·
วงล้อมคือ *clash* (§7 · BUGS_SEEN §D2)

**เขตไหนได้วง (กติกาเลือก — เจ้าของเคาะไว้แล้ว 2026-08-25):**
ทุกเขตที่หมุดหรือปลายลูกศรของฉากตกอยู่ข้างใน และต้องผ่านสามข้อ —
มีส่วนมองเห็นจริงในกล้อง · กรอบเขตไม่ใหญ่เกิน **2 เท่า** ของกล้อง ·
ฉากกล้องกว้าง (>72% ของแผ่น) ไม่ตีวงเลย
ฉากท้องพระโรงที่หมุดชี้ที่อยู่แล้ว **ไม่มีวง** — ตีทั้งมณฑลไม่เพิ่มข้อมูล มีแต่สิ่งรบกวน

**★ หมุดอ้างอิง `focus:false` (2026-08-26):** หมุดที่ฉากชี้เป็น *ปลายทาง/จุดอ้าง*
ไม่ใช่เวทีของฉาก ใส่ `focus:false` แล้วมันจะไม่ดึงเขตของตัวเองเข้าวง (หมุดยังแสดงปกติ)
· เกิดจาก c1-03: หมุด "ฉางอาน — ปลายทาง" ลากกวานจงทั้งเขตเข้าวง ทั้งที่ฉากพูดถึงแอ่งหลงโย่ว
— เจ้าของสั่ง "วงแค่หลงโหย่ว" · ใช้เท่าที่จำเป็น: หมุดส่วนใหญ่คือเวทีของฉากจริง ๆ

**รูปวง (ล็อกทั้งห้าข้อ — เจ้าของเกลารอบสอง 2026-08-25: "อยากได้แบบ ก แต่แปลกน้อยลง"):**
1. **เส้นขอบรวมของกลุ่มเขต** — เขตติดกันหลายเขตได้วงเดียว **ห้ามวาดพรมแดนภายในกลุ่ม
   และห้ามมีเส้นซ้อนสองชั้นบนพรมแดนร่วม** · สร้างจาก `TK.regionArcs` (§16):
   arc ที่มี "ข้างเดียว" อยู่ในกลุ่ม = ขอบของกลุ่ม · ห้าม union รูปเองตอนรัน
2. **วาดเฉพาะเส้นที่มีความหมาย** — arc มีชนิดติดมาจาก build_geo:
   | ชนิด | ปฏิบัติ |
   |---|---|
   | เขตต่อเขต และ `t:"line"` (สุดเขตที่เกาะแนวเส้นพิมพ์) | เส้นประทอง + casing เต็ม |
   | `t:"coast"` (ชายฝั่ง/ริมน้ำ) | เส้นประบาง 1.4px จาง .45 ไม่มี casing |
   | `t:"edge"` (ขอบแผ่น) และ `t:"open"` (สุดเขตการโตเฉย ๆ) | **ไม่วาด** |
   สองชนิดสุดท้ายคือ "เหลี่ยมประหลาดตามขอบแผนที่" ที่เจ้าของทัก — มันไม่ใช่พรมแดนของอะไรจริง ๆ

## §19 · เลย์เอาต์ป้ายของฉาก (ล็อก 2026-08-26 — เจ้าของเคาะหลังดูภาพจริงรอบสาม)

หลักเดียว: **มองแวบแรกต้องรู้ว่าป้ายไหนของใคร** — ไม่ต้องอ่านนิยายก่อนถึงจะอ๋อ

กลไกทั้งหมดอยู่ใน `layoutAnnotations()` (strategic.js) — ฉากไม่ต้องตั้งค่าอะไร ยกเว้นข้อ 5:

1. **เส้นทางทุกเส้น (ไม่รวม echo) เป็นสิ่งกีดขวางชั้นอ่อน** — สุ่มจุดทุก ~22px จอ
   ป้ายหาที่ที่ไม่ทับเส้นก่อนเสมอ (วงชิด → วงไกล ~เท่าตัว) · ฉากแน่นจนไม่มีที่ค่อยยอมทับ
2. **เส้นโยง (leader)** — ป้ายที่ขอบกล่องไกลจุดยึดเกิน 26px ได้เส้นสองชั้น (สว่างบนขอบมืด
   `.mk-leader/.mk-leader-under`) พากลับไปหาเจ้าของ · เฟดพร้อมป้าย · แนวเส้นถูกจอง
   กันป้ายอื่นคร่อม · ป้ายในวงชิดไม่มีเส้น — เส้นโยงคือข้อยกเว้น ไม่ใช่ธรรมเนียม
3. **Sent to front** — จัดตำแหน่งเสร็จ ยกทั้งชั้นขึ้นบนสุดของ DOM: เส้นโยงเหนือเส้นทาง ·
   ป้ายเหนือเส้นโยง · คำบรรยายของฉาก (rank 0) บนสุด
4. **ขอบเฟรมเป็นกติกาตอนหาที่ + clamp ท้ายสุด** — ป้ายหลุดจอ = ป้ายที่หายไปเฉย ๆ
5. **`chip:"head"` บน marker ลูกศร** — ลูกศรที่ความหมายคือ "เข้าประจำที่ปลายทาง"
   (เช่น ห่าวเจา 1,000 เข้าป้อม c6-03) ยึดป้ายที่หัวลูกศร · ค่าปกติเกาะกลางเส้น
   ซึ่งถูกแล้วสำหรับการเดินทัพยาว ๆ
6. **หมุดต้องยืนที่ตำแหน่งหน้าที่ของมัน ไม่ใช่ตำแหน่งที่ว่าง** — กองที่ทำหน้าที่กัน/คุม
   ต้องยืน *ระหว่าง* สิ่งที่กันกับสิ่งที่ถูกกัน (ม้าเชียงย้ายจากช่างกุยไปฉินชวงกลางระเบียง
   เทียนสุ่ย–อานติ้ง c4-10) — ถ้าไม่มีหมุดให้ยึด วัดจากแผ่นจริงแล้วเพิ่ม (วิธี: crop
   `assets/map.jpg` เทียบ dot ที่สอบเทียบแล้วในครอปเดียวกัน — ฉินชวงวัดได้ ±3)
