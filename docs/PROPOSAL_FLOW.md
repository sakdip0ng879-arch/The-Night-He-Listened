## 1. Flow — เคาะทีละเฟส ประตูปิดแล้วไม่กลับ

ปัญหาของสองโปรเจกต์ก่อนคือเนื้อเรื่อง กฎ และโค้ด ถูกแก้พร้อมกันตลอด พอแก้เนื้อเรื่อง เส้นทางพัง
พอแก้เส้นทาง ตัวเลขพัง เสนอให้ **ล็อกทีละชั้น และชั้นล่างห้ามขยับหลังปิด**

```
เฟส 0  เนื้อเรื่อง        ← อยู่ตรงนี้
       รีวิว → เจ้าของเคาะหมวด A/B/C → แก้ต้นฉบับให้จบ → LOCK
       ผลลัพธ์: What_If_Zhao_Yun_Remonstrance.md = source of truth · ห้ามแก้อีก

เฟส 1  กฎ + เครื่องมือ
       ยก engine/css/tools จากโปรเจกต์ 1–2 → รื้อกฎที่ซ้ำซ้อน → DECISIONS.md ฉบับเดียว
       + เขียนกฎเดินทัพใหม่ (ข้อ 2 ข้างล่าง) → LOCK
       ผลลัพธ์: กฎมีที่อยู่ที่เดียว · ไม่มี "_v1_inherited" อีก

เฟส 2  กระดาน
       places.js · roads.js (ใหม่) · geo.js · names.js · ตัวเลขตั้งต้นปี 221
       + ปรับ labeler.js ให้ตัดคำไทยได้ + เลือกฟอนต์ → LOCK
       ผลลัพธ์: แผนที่เปล่าที่เดินทัพได้ ก่อนมีฉากสักฉาก

เฟส 3  เขียนทีละบท  ← วนซ้ำ
       บทที่ N:  storyboard → ฉาก → เส้นทาง → build → ตัวตรวจ → เจ้าของรีวิว → LOCK บทนั้น
       ผลลัพธ์: บทที่ปิดแล้วไม่กลับมาแก้

เฟส 4  รวมเล่ม
       ตรวจข้ามบท · ไทม์ไลน์ทั้งเรื่อง · บัญชีกำลังพลทั้งเรื่อง · README
```

## 2. ★ ข้อเสนอหลัก — เลิกวาดเส้น เปลี่ยนเป็นกราฟถนน

นี่คือคำตอบตรง ๆ ต่อกฎใหม่ที่เจ้าของตั้ง

### ปัญหาของวิธีเดิม

โปรเจกต์ 1–2 เก็บเส้นทางเป็น **เส้นโค้ง SVG ที่วาดด้วยมือ**

```js
hanzhong_qishan: { label:"…", d:"M 477,805 C 445,796 416,788 396,776 C 358,757 …" }
```

แล้วให้ `check_routes.js` ตรวจย้อนหลังว่า *คด 3% ไหม · อยู่บนบกไหม · หัวท้ายตรงเมืองไหม*
ต่อมาเพิ่ม *flips ≤ 1 · maxTurn ≤ 55°* (HANDOFF §2.13)

**กฎพวกนี้ตรวจ "รูปร่าง" ไม่ได้ตรวจ "เส้นทาง"** เส้นที่โค้งสวยได้ 7° แล้วลอยข้ามภูเขาสามลูก
กับแม่น้ำหนึ่งสาย ผ่านทุกข้อ และ HANDOFF §2.5 ก็บันทึกอาการไว้แล้วว่าคนเขียนจะเริ่ม
*"ขยับจุดควบคุมจนตัวเลขผ่าน"* ซึ่งคือการโกหกภูมิประเทศเพื่อให้ผ่านตัวตรวจ

**กฎ 3% ไม่ได้แค่ไม่พอ มันชวนให้โกง**

### ข้อเสนอ — `roads.js` เป็นกราฟ แล้วให้ engine สร้างเส้นเอง

**ชั้นที่ 1 — จุด (node)** ทุกจุดที่กองทัพหยุด/ผ่านได้จริง

```js
// ประเภท: city · pass · ford · valley_mouth · well · junction
tianshui:   { type:"city",         xy:[356,607] },
jieting:    { type:"pass",         xy:[348,549], note:"คอขวดถนนสันเขา Long" },
jincheng:   { type:"ford",         xy:[292,468], river:"yellow" },
xiegu_kou:  { type:"valley_mouth", xy:[516,663] },
```

**ชั้นที่ 2 — ถนน (edge)** ต่อจุดกับจุด หนึ่งช่วง = ถนนจริงหนึ่งช่วง

```js
{ a:"tianshui", b:"jieting", terrain:"ridge",  li:180,
  d:"M 356,607 C …",                    // รูปช่วงนี้ วาดครั้งเดียว ใช้ตลอดเรื่อง
  wagons:true },
{ a:"tianshui", b:"chencang", terrain:"gorge", li:220,
  wagons:false, note:"หุบเขาแม่น้ำ Wei — คนผ่านได้ เกวียนไม่ได้ (STORY_REVIEW A2)" },
```

**ชั้นที่ 3 — การเดินทัพ** ประกาศเป็น **รายชื่อจุด** ไม่ใช่เส้น

```js
c3_02_zhangfei: {
  side:    "han",
  commander:"Zhang Fei",
  troops:  15000,
  path:    ["hanzhong","yangpingguan","wudu","xiabian"],   // ← เขียนแค่นี้
  year:221, season:"autumn"
}
```

engine ต่อ `d` ของแต่ละ edge เข้าด้วยกันแล้ววิ่งลูกศรตามนั้น

### ทำไมมันตอบโจทย์ที่เจ้าของตั้งไว้ทุกข้อ

| กฎที่เจ้าของบอก | วิธีเดิม | กราฟถนน |
|---|---|---|
| เดินเมืองต่อเมือง จุดต่อจุด | หวังว่าคนวาดจะวาดถูก | **เป็นไปไม่ได้ที่จะไม่เป็นแบบนั้น** — path คือรายชื่อจุด |
| ต้องผ่านด่าน ห้ามอ้อมข้าม | ตรวจไม่ได้เลย | ด่านคือ node · ไม่มี edge ที่อ้อมมัน = อ้อมไม่ได้ |
| ห้ามโค้งข้ามแม่น้ำ | ตรวจไม่ได้เลย | edge ข้ามน้ำมีเฉพาะที่ `type:"ford"` |
| ห้ามโค้งทะลุทุกอย่าง | ตรวจ "ความคด" ซึ่งไม่เกี่ยวกัน | edge มีเฉพาะที่ถนนมีจริง |
| ทุกเส้นต้องบอกว่าของใคร ยกไปเท่าไหร่ | เป็น field ที่ *ลืมใส่ได้* | `side` + `troops` อยู่ใน schema · ไม่มี = build ไม่ผ่าน |
| เลิกใช้กฎโค้ง 3% | — | **ลบทิ้งทั้งข้อ** รูปเส้นมาจากภูมิประเทศ ไม่ใช่จากเกณฑ์ความสวย |

### ของแถมที่ได้ฟรี

1. **วาดครั้งเดียวใช้ตลอดเรื่อง** — ถนน Hanzhong→Chencang ถูกใช้ 5 ครั้งใน 40 ปี วิธีเดิมวาด 5 เส้น
   (และเพี้ยนกันทั้ง 5) วิธีใหม่คือ edge เดียวกัน **แปลว่าเส้นทางเดียวกันจะเหมือนกันเป๊ะเสมอ
   ซึ่งคือสิ่งที่เจ้าของขอไว้ในโปรเจกต์ 2 ว่า "เลือกสัก standard"**
2. **ระยะทางเป็นลี้ได้ฟรี** — บวก `li` ตามช่วง → ตรวจได้ทันทีว่า *"เดินทัพ 1,200 ลี้ใน 8 วัน"*
   ของ Sima Yi ตรงกับแผนที่จริงไหม และคำนวณเวลาเดินทัพของทุกกองได้
3. **เสบียงคำนวณได้** — `wagons:true/false` + `li` = รู้ว่าเส้นไหนส่งเสบียงได้
   **ซึ่งคือแก่นของเรื่องนี้ทั้งเรื่อง** (ดูโหมด V2)
4. **ตัวตรวจง่ายลงมาก** — `check_routes.js` เดิม 27 KB เต็มไปด้วยฮิวริสติกและตาราง `STRAIGHT_OK`
   `SHAPE_OK` ที่เป็นการยกเว้นด้วยมือ · ของใหม่ตรวจแค่ **"edge นี้มีจริงไหม"** และ
   **"หัวท้ายต่อกันไหม"** — ตาราง `STRAIGHT_OK` / `SHAPE_OK` **หายไปทั้งสองตาราง**
5. **ถอยกลับทางเดิมได้ฟรี** — กลับ array ก็ได้เส้นถอย ไม่ต้องวาดเส้นใหม่ ไม่ต้องมี flag `reverse`

### ราคาที่ต้องจ่าย (พูดตรง ๆ)

- **งานเฟส 2 หนักขึ้น** — ต้องวาด edge ทุกช่วงก่อนเขียนฉากแรก ประเมิน **35–50 edges** สำหรับเรื่องนี้
  ราวหนึ่งรอบทำงานเต็ม ๆ · แต่มันคือ **งานที่วิธีเดิมก็ต้องทำอยู่ดี แค่กระจายไปทำตอนเขียนฉาก
  ทีละเส้น อย่างไม่สม่ำเสมอ**
- **ต้องแก้ engine** — ส่วนที่วิ่งลูกศรใช้ `path.getPointAtLength()` อยู่แล้ว
  เปลี่ยนแค่ที่มาของ `d` **ประเมินว่าแตะ `engine.js` ไม่เกิน 60 บรรทัด**
- ถ้าเรื่องต้องการเส้นที่ไม่มีในกราฟ (เช่นเดินลัดทุ่ง) → เพิ่ม edge พร้อมเหตุผล
  **ซึ่งคือการตัดสินใจที่มองเห็น ไม่ใช่การเผลอ**

## 3. กฎที่ควรรื้อทิ้งหรือยุบ (ดูคร่าว ๆ — รอทำจริงในเฟส 1)

จากการสแกน `DECISIONS.md` ของสองโปรเจกต์ + `HANDOFF.md` §2 (18 ทุ่นระเบิด) เห็นสามอาการ

1. **กฎซ้อนกฎ** — D11 (ห้ามเส้นตรง) → §2.5 (ห้ามดัดเส้นให้ผ่าน D11) → §2.13 (มาตรฐานรูปทรง)
   → §2.5 อีกรอบในรูป `SHAPE_OK` · **สี่ชั้นที่แก้ปัญหาเดียวกัน** และข้อเสนอในข้อ 2 ลบทั้งกองได้
2. **กฎที่จริง ๆ แล้วเป็นบั๊ก** — เช่น §2.10 (`setAttribute('fill')` แพ้ CSS) ไม่ใช่กฎการเล่าเรื่อง
   มันคือบั๊กที่ควรแก้ในโค้ดแล้วลบข้อออก · ควรแยก **"กฎ"** ออกจาก **"บั๊กที่เคยเจอ"** เป็นคนละไฟล์
3. **ไฟล์ `_v1_inherited`** — โปรเจกต์ 2 มี `DECISIONS.md` + `DECISIONS_v1_inherited.md` +
   `SCHEMA_v1_inherited.md` + `GLOSSARY_EN_v1_inherited.md` = กฎอยู่สี่ที่ **โปรเจกต์นี้ควรมีไฟล์เดียว**
   ยกมารวม แล้วลบต้นฉบับที่ยกมาทิ้ง (ของเดิมยังอยู่ในโฟลเดอร์เก่า)

**เป้าหมายเฟส 1: `DECISIONS.md` ไฟล์เดียว + `BUGS_SEEN.md` ไฟล์เดียว จบ**

## 4. โหมด visual ที่เสนอ

เรียงตาม **(คุ้ม/แพง)** · เสนอให้เลือก 2–3 ไม่ใช่ทั้งหมด

### V1 · โหมดถนน ★ แนะนำ · ถูกมาก
เปิด/ปิดกราฟถนนทับแผนที่ ให้เห็นถนน ด่าน และท่าข้ามที่มีอยู่จริง แล้วลูกศรวิ่งทับมัน
**คนอ่านจะเห็นว่าทำไมกองทัพต้องไปทางนั้น ไม่ใช่แค่เห็นว่ามันไปทางนั้น**
เป็นผลพลอยได้ของข้อ 2 โดยตรง — ข้อมูลมีอยู่แล้ว เหลือแค่วาด **ประเมิน: ครึ่งวัน**

### V2 · โหมดเสบียง ★★ แนะนำที่สุด · ปานกลาง
เรื่องนี้ทั้งเรื่องคือเรื่องเสบียง ไม่ใช่เรื่องรบ — *"เราจะปลูกมันในทุ่งของศัตรูแล้วไหลลงมาตามแม่น้ำ Wei"* ·
*"จุดที่เส้นเลือดสองเส้นมาบรรจบกัน"* · *"ข้าวหมดก่อนที่ศัตรูจะหมดแรง"* · Li Yan · Jie Ting ·
Wuzhang — **ทุกจุดพลิกของเรื่องเป็นเรื่องเสบียงหมด**

โหมดนี้แสดง: คลัง → เส้นส่ง → แนวหน้า พร้อมระยะเป็นลี้ · เส้นที่ถูกตัดเปลี่ยนเป็นสีแดง
**ฉากที่มันจะเปล่งประกาย:** ปี 231 ที่ Sima Yi ยึด Jie Ting แล้วทัพฮั่นถูกตัดขาดใน 6 วัน —
ตอนนี้เป็นประโยคเดียว โหมดนี้ทำให้มันเป็นภาพที่ดูแล้วเข้าใจทันที
**ต้องมี `wagons` + `li` จากข้อ 2 ก่อน · ประเมิน: 1–2 วัน**

### V3 · โหมดสองเอกภพ (ghost) ★★ แนะนำ · ปานกลาง
เรื่องนี้เปรียบเทียบกับเอกภพของเราตลอดเวลา (*"ในเอกภพของเรา…"* โผล่นับสิบครั้ง)
และ **ฉากที่ดีที่สุดของเรื่องคือฉากที่เอาสองเอกภพมาซ้อนกันตรง ๆ** (ทุ่ง Wuzhang ปี 234)

โหมดนี้ซ้อนเส้นแบ่งของเอกภพจริงเป็นเงาจาง ๆ ทับเส้นแบ่งของเอกภพนี้ ในปีเดียวกัน
ปี 234: เอกภพนี้ฮั่นถือกวานจงทั้งแอ่ง · เอกภพจริงฮั่นถือ **ศูนย์** — คนอ่านเห็นสิบสามปีของเรื่องในภาพเดียว
**ไม่มีโปรเจกต์ไหนก่อนหน้ามีโหมดนี้ และเรื่องนี้เป็นเรื่องเดียวในสามเรื่องที่โครงสร้างเรียกร้องมันขนาดนี้**
ต้องมีข้อมูลเส้นแบ่งจริงเพิ่มราว 6–8 ปีสำคัญ (ยกจากโปรเจกต์ 1 ได้บางส่วน) **ประเมิน: 1–2 วัน**

### V4 · แผงราคา (cost ledger) ★ น่าสนใจ · ถูก
เจ้าของบอกว่า *"ทุกอย่างในเรื่องนี้มันได้มายาก และต่างมีราคาทั้งหมด"* — ทำให้ธีมเป็นตัวเลขที่เดินตามเรื่อง
แผงเล็ก ๆ มุมจอ: **ปีที่ผ่านไป · คนที่ตายไปแล้ว · ชื่อที่เสียไป**
(Ma Chao 222 · Zhang Fei 223 · Liu Bei 226 · Zhao Yun 229 · Ma Dai 231 · Zhuge Liang 234 …)
ชื่อเพิ่มเข้ากองทีละชื่อขณะเลื่อนอ่าน **ประเมิน: ครึ่งวัน ถ้ามีบัญชีกำลังพลอยู่แล้ว**

### V5 · ตัวนับม้า · ถูกมาก
0 (221) → 12,000 → 40,000 (226) เดินขึ้นตามเรื่อง พร้อมป้ายว่า *"ที่ราบยังรบไม่ได้"* → *"รบได้แล้ว"*
เป็นวิทยานิพนธ์ครึ่งหนึ่งของเรื่องในตัวเลขเดียว **แต่ต้องล็อกบัญชีม้าก่อน (STORY_REVIEW A10)**
