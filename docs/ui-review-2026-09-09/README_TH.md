## 1 · เมืองและระดับซูม

ตรวจข้อมูลปัจจุบันพบ 107 สถานที่ ทุกแห่งมี label: เมืองหลวง 7 เมือง 35 เมืองรอง 38 และสถานที่ประเภทอื่น 27 แห่ง มี 94 แห่งระบุชื่อบนแผ่นต้นฉบับ ส่วน chk ปัจจุบันเหลือ 8 แห่ง คู่มือเก่าบางส่วนยังระบุจำนวนก่อนแก้

จุดขาวจึงไม่ได้แปลว่าไม่มีชื่อในไฟล์: renderer ลดไอคอนเป็นจุดตามขนาด/การชน และตัวจัดป้ายคัดชื่ออีกครั้ง ขณะเดียวกัน assets/map.jpg มีสถานที่ย่อยอีกหลายแห่งที่ยังไม่ได้เพิ่มใน places.js จึงไม่ควรอ้างว่าปรับ LOD อย่างเดียวแล้วจะครบเหมือนต้นฉบับ

ข้อเสนอให้ใช้พื้นที่ว่างบนจอจริงตัดสิน ไม่ใช้จำนวนป้ายตายตัวเป็นตัวหลัก:

| มุมมอง | หมุด | ชื่อ |
|---|---|---|
| ทั้งแผ่นดิน | เมืองหลักเป็นรูป เมืองรองเป็นจุดเล็กที่มีพื้นที่คลิกกว้างกว่า | เมืองหลวง/เมืองเอก/เมืองในฉาก ประมาณ 12–18 ชื่อเป็นงบเริ่มทดลอง |
| ภูมิภาค | รูปเมืองกับด่านที่แยกกันได้ จุดเล็กยังบอกความหนาแน่น | เพิ่มเมืองรองตามพื้นที่ว่าง ประมาณ 25–40 ชื่อ |
| ใกล้ | รูปและชื่อของสถานที่ที่สอบตำแหน่งแล้ว | เปิดทุกชื่อที่วางได้โดยไม่ชน; ที่เหลือเปิดเมื่อชี้/แตะ/ค้นหา |

ตัวเลขข้างบนเป็นเป้าหมายทดลอง ไม่ใช่ข้อมูลภูมิศาสตร์ รอบนี้ตัวอย่าง studio ปรับเพดานชื่อเป็น 18–72 ตามพื้นที่จอจริงแล้ว โดยลำดับความสำคัญและการหลบยังเป็นผู้คัดชื่อ ไม่ได้บังคับให้มีจำนวนเท่ากับเพดาน และใช้สเกลจริงเมื่อแผนที่มีขอบว่าง การซูมต้องรักษาชื่อที่เพิ่งเลือกไว้เพื่อลดการกระพริบ เมืองในฉากและเมืองที่เลือกมาก่อนชื่อมณฑล ชื่อฉากยาวควรย้ายออกก่อนลดชื่อเมือง

ไม่ควรใช้การรวมกลุ่มแบบหมุด “+20” เป็นหน้าหลัก เพราะจะสูญเสียภาพความหนาแน่นเว่ยที่ผู้ใช้ต้องการ เพิ่มทะเบียนสถานที่ต้นฉบับแยกจากเมืองที่มีบทในเรื่อง ตรวจชื่อ/พิกัดทีละจุดก่อนนำเข้า ห้ามสร้างเมืองจากช่องว่างบนแผนที่

## 2 · UI ที่ลองได้แล้ว

- ปุ่มอยู่แถบบนที่กันพื้นที่ไว้จริง จึงไม่บังหัวแผนที่
- ตำแหน่งที่กำลังดูและกำลังพลย้ายมาอยู่ฝั่งอ่าน
- ค้นหาชื่อไทย/อังกฤษจาก places.js เปิดการ์ดเมือง และกลับเข้าฉากเดิมได้
- ปุ่มขยายแผนที่พักคอลัมน์อ่านได้
- ส่วน “มุมมองสรุปเหตุการณ์” ทดลองป้ายสั้นและเลือกขบวนเดียวได้ ใช้ข้อมูล marker เดิม แสดงสภาพเมื่อฉากจบ ไม่ใช่การเปลี่ยนลำดับเวลา
- รายละเอียดเพิ่มเติมเปิดเมื่อขอ ไม่ควรแสดงทุกแผงพร้อมกันบนหน้าจอเล็ก

ตัวอย่างนี้ยังไม่ใช่ดีไซน์ที่เคาะทั้งระบบ บนมือถือใช้แผนที่เหนือเรื่องและแถบปุ่มย่อ พร้อมปุ่มเปิดค้นหา/กำลังพลแล้ว แต่ป้ายเหตุการณ์ยาวบนแผนที่ยังต้องเกลาสำหรับจอแคบ

## 3 · ภาพการเดินทัพและข้อความ

ให้แผนที่บอก **ที่ไหน/ไปทางใด/ใครอยู่ตรงนั้น** และให้คอลัมน์อ่านบอก **ทำไม/ผลคืออะไร** ป้ายข้างเส้นทางใช้ชื่อผู้บัญชาการกับกำลัง ส่วนประโยคยาวเปิดในรายการเหตุการณ์ได้ ตัวอย่างป้ายสั้นเป็นข้อเสนอด้านหน้าจอ ไม่เปลี่ยนต้นฉบับเรื่อง

ศึกหลายกองควรมีภาพรวมก่อน แล้วเลือกดูกองจากรายการ การแยกให้ดูทีละกองไม่ได้แปลว่าทุกกองออกเดินคนละเวลา; ใช้ wave เดิมเมื่อเรื่องยืนยันลำดับเท่านั้น

ข้อเสนอฉากเด่น:

- c4-10: เข้าตี → ตรึง → ถอน ไม่ให้สี่เส้นทางแข่งขันกันตั้งแต่เฟรมแรก
- c6-14: แยกกองหลังที่มู่เหมินกับสองขบวนถอน
- c7-11: ยึดสัน → กองแยกใต้ → กำลังหนุน และย้ำว่าได้สันยังไม่ได้ด่าน
- c8-07: เลือกกอง 1–5 จากรายการ มีภาพรวมเส้นทางทุกกองให้กลับมาดู
- c9-09: แผนภาพข้าว 10 กระสอบเหลือ 3 ข้างเรื่อง มีสายเสบียงบนแผนที่เพียงสายเดียว
- c11-05: หกกองแต่เพียงห้ากองมีเส้นเคลื่อน กองหกต้องอยู่กับที่
- c11-10: เทียบเส้นเดิมปี 270 กับ 274 เห็นว่าเปลี่ยนคน ไม่ได้เปลี่ยนแม่น้ำ

การเดินทางที่น่าพัฒนาเพิ่ม: c1-08 หลางจง–เฉิงตู, c2-08 ส่งฎีกา, c9-03 ข่าวไปกลับ 40 วัน, c11-09 จดหมายส่งคืน ต้องตรวจเส้นทางบนกราฟก่อนทำ เส้นข่าวสารไม่ควรใช้รูปกองทัพ บทสนทนา/การสูญเสียในภาค 5 และบทส่งท้ายควรเงียบและคงกล้องไว้

## 4 · ความลื่น: ผลรอบส่งงาน

วัดด้วย Chrome headless บนเครื่องนี้ ขนาด viewport 1904×980 สองรอบต่อชุด ไม่ใช่คำรับรอง FPS ของทุกอุปกรณ์

| การลาก | ก่อน | หลัง |
|---|---|---|
| เวลากลางต่อเฟรม | 116.6 / 150.2 ms | 16.7 / 16.7 ms |

ก่อน: `tools/_ui-audit/baseline/results.json` หลัง: `tools/_ui-audit/improved/results.json` ทดลองปิด filter ทั้งหมดอย่างเดียวไม่แก้ปัญหาได้พอ

สิ่งที่แก้ในหน้าปกติด้วย:

1. กล้องเลื่อน SVG ด้วย CSS compositor transform และ commit viewBox เมื่อหยุด; รวมขอบว่างของ preserveAspectRatio ในสูตร
2. ป้ายจัดใหม่หลังกล้องจบจริง แทนตั้งเวลาคาดว่าจบ; ยกเลิกกล้องด้วยการคลิกก็คืนป้ายได้
3. ขบวนเริ่มหลังกล้องเข้าที่ รักษา delay/wave เดิม และยกเลิกคิวเมื่อเปลี่ยนฉาก
4. ปุ่มเลือกฉากพาคอลัมน์เรื่องไปต้นฉากทันที ลดปัญหาการเลื่อนข้ามหลายฉากและปลดล็อกด้วยเวลาเดา

เพิ่มชั้นพื้น Canvas ที่ประกอบกระดาษ ป่า สีพื้นที่ และเงาภูเขาจากงานเดิมไว้ล่วงหน้า ส่วนแม่น้ำ หมุด ป้าย และขบวนยังเป็น SVG เดิม ไฟล์ภาพที่ใช้รวมประมาณ 6.9 MB ขนาด 1650×1950 (พิกัดแผ่นเดิม) โหลดไม่สำเร็จจะใช้ SVG เดิมต่อโดยไม่ซ่อนแผนที่

ผลสุดท้ายดู performance-final.json: ลากค่ากลาง **16.7 / 16.7 ms**; เปลี่ยนฉาก **16.7 / 16.7 ms**, p95 **33.9 / 66.6 ms**, มีเฟรมเกิน 50 ms **3 / 5 เฟรม** ในช่วงวัดประมาณ 1.6 วินาที จึงดีขึ้นชัดเจนแต่ไม่ได้หมายความว่าทุกเฟรมทุกเครื่องได้ 60 FPS

**อัปเดตตามคำขอเรื่องสี:** คืนการเปลี่ยนสีอย่างนุ่มนวลด้วยภาพพื้นเก่าซ้อนภาพใหม่ เฟด opacity 700 ms แบบ ease-in-out วาดพื้นใหม่เพียงครั้งเดียวแล้วให้ compositor จัดการ ไม่คำนวณหน้ากากภูเขาซ้ำทุกเฟรม เริ่มเมื่อ engine ปล่อยเจ้าของหลังทัพถึงเหมือนเดิม ถ้าเปลี่ยนสีซ้ำกลางเฟดจะประกอบภาพที่เห็นจริงเป็นจุดเริ่มถัดไป; init/scrub และ reduced motion แสดงสีปลายทางทันที

วัดหลังเพิ่มเฟด: ลากค่ากลาง 16.7 / 16.7 ms เปลี่ยนฉาก 16.7 / 16.7 ms, p95 50.3 / 50.1 ms, เฟรมเกิน 50 ms รอบละ 4 เฟรม ดู performance-fade.json นี่ยังเป็นการวัดบนเครื่องนี้ ไม่ใช่คำรับรองทุกเครื่อง

ชั้นพื้นใช้สีฝ่ายจาก attribute SVG เดิม ไม่ทำสำเนารายชื่อเจ้าของ รักษา opacity ทั้งกลุ่ม .45, stroke ปิดรอยต่อ 1.5, ป่า .82, เงาภูเขา .72 แบบ multiply และเกรนกระดาษเดิม งาน raster ดูนุ่มขึ้นเมื่อขยายมาก; หมุด ป้าย แม่น้ำและแนวมณฑลยังเป็นเส้นคม

ใช้ ?renderer=svg เพื่อเทียบกับวิธีวาดเดิม เมื่อแก้ภาพ/หน้ากากต้นฉบับให้เปิด server 8778 แล้วรัน node tools/build_map_cache.js จากนั้น node tools/check_map_cache.js ภาพที่สร้างแล้วส่งไปกับเว็บ; ผู้อ่านไม่ต้อง build และเปิด file:// ได้

ภาพชุด improved ตรวจเฉพาะแผนที่: คอลัมน์เรื่องในชุดนั้นยังอยู่บทนำ เพราะชุดแรกเรียก engine โดยตรง ห้องรีวิวตัดส่วนคอลัมน์ออกด้วย CSS; กด “ทดลองฉากนี้” เพื่ออ่านฉากที่ตรงกัน เครื่องมือถ่ายภาพปรับให้เลื่อนคอลัมน์ตรงฉากแล้วสำหรับรอบถัดไป

ภาพและผลวัดขนาดใหญ่ถูก ignore ใน Git ไม่ส่งขึ้น Pages สร้างใหม่ด้วย `node tools/audit_ui.js improved --scenes` แล้ว `node tools/build_ui_review.js` ต้องมีเซิร์ฟเวอร์ 8778 ก่อน เปิดห้องรีวิวในสำเนาเครื่องนี้ได้เลย

งานไอคอนพักไว้ตามคำสั่ง และยังไม่ได้ commit/push/deploy

## เกลารายการกองทัพ

UI studio แสดงการ์ดกองทัพพร้อมสีฝ่าย จำนวนคน ชนิดขบวน และต้นทาง–ปลายทางตาม routeMeta (กลับทิศตาม reverse) ใช้กับทุกฉากที่มี arrow โดยไม่เขียนลำดับเวลาใหม่ เลือกขบวนแล้วเน้นการ์ดที่เลือก เหลือเส้นทัพเส้นเดียว คงหมุดเหตุการณ์พร้อมป้ายชื่อสถานที่สั้น รายละเอียดต้นฉบับยังอยู่ในรายการ กดคืนภาพฉากเพื่อดูภาพรวมเดิม
