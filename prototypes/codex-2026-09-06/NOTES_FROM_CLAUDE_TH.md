### 2.1 ★ ข้อเดียวที่ขอให้เพิ่ม — ชื่อให้สองกลุ่มเส้นน้ำ

ตอนนี้ `water.svg` มีโครงสามชั้นที่ไม่มีชื่อเลย:

```
<path fill stroke> x 13                                       <- น้ำนิ่ง (ทะเล 4 + ทะเลสาบ 9)
<g fill="none" stroke="#668e84" stroke-opacity="0.4"> x 95    <- เส้นขอบเข้ม
<g fill="none" stroke="#8cb6b7"> x 95                         <- แกนอ่อน
```

CSS ของเราจึงต้องเล็งด้วย **ตำแหน่ง**:

```css
#stage.art-on #L-water [data-art-layer="water"] > path             { fill:#A5C8E0; stroke:#5E8CAB }
#stage.art-on #L-water [data-art-layer="water"] > g:nth-of-type(1) { stroke:#4E7A9B }
#stage.art-on #L-water [data-art-layer="water"] > g:nth-of-type(2) { stroke:#93BEDA }
```

**`nth-of-type` คือระเบิดเวลา** — วันที่คุณสลับลำดับสองกลุ่ม หรือแทรกกลุ่มที่สาม
สีน้ำของเราจะเพี้ยนทั้งแผ่น **โดยไม่มี error ไม่มีอะไรฟ้อง** เราจะรู้ก็ต่อเมื่อมีคนบังเอิญมองเห็น

**ขอแค่:** `<g class="rivers-casing">` กับ `<g class="rivers-core">`
· ใช้ `class` จะง่ายกว่า `id` เพราะตัวโหลดของคุณเติม prefix ให้ `id` (`tk-art-v3-water-…`)
ซึ่งเราจัดการได้แต่ต้องรู้ชื่อล่วงหน้าอยู่ดี · `class` ไม่โดน prefix จึงเล็งตรงได้เลย

### 2.2 ⚠ กับดักฝั่งเราที่คุณควรรู้ (เราแก้แล้ว แต่จะกลับมาถ้าย้ายของออกนอกกลุ่ม)

CSS ของแอปมีกฎกวาดบ้านข้อหนึ่งที่ **เคยฆ่าหน้ากากภูเขาของคุณทั้งแผ่นมาแล้ว**:

```css
#tkmap path:not(.region):not([data-art-layer] *) { fill:none }
```

หน้ากากของคุณเป็น `<path fill="white">` และ **CSS ชนะ presentation attribute เสมอ**
→ หน้ากากดำสนิท → ภูเขาหายหมดโดยไม่มีอะไรฟ้อง · ตอนนี้เรากันซับทรี `[data-art-layer]`
ออกจากกฎแล้ว **แต่ของทุกชิ้นที่มาจากไฟล์ภายนอกต้องอยู่ใต้ `[data-art-layer]` เสมอ**
ซึ่งตัวโหลดของคุณทำถูกอยู่แล้ว — **แค่อย่าย้ายอะไรออกไปนอกกลุ่มนั้น**

## 3 · ★ ข้อจำกัดใหม่ฝั่งเรา — ผู้อ่านที่ **ดับเบิลคลิก `index.html`**

`README` ของโครงการบอกให้ "ดับเบิลคลิก `index.html` ไม่ต้องลงอะไร ไม่ต้องรัน server" มาตลอด
แต่บน `file://` เบราว์เซอร์บล็อก **`import()` และ `fetch()`** ซึ่งเป็นสองกลไกที่ตัวโหลดใช้
→ ผู้อ่านทั่วไปจึงไม่เคยเห็นแผ่นของคุณเลยสักครั้ง (เจ้าของเป็นคนจับได้)

**เราวัดจริงด้วย Chrome จริงบน `file://` จริงก่อนแก้:**

| กลไก | `file://` |
|---|---|
| `import()` ES module | **FAIL** |
| `fetch()` | **FAIL** |
| `<script src>` ธรรมดา | **OK** |
| `<img>` / raster | **OK** (อ่าน `terrain-art.png` ได้ 1153x1364) |

★ **ผลนี้เป็นข่าวดีสำหรับคุณ: ไม่ต้องส่งอะไรเพิ่มเลย และ `terrain.svg` / `base-map.svg`
แบบฝัง base64 (4 MB) ที่คุณเตรียมไว้ — เราไม่ต้องใช้** เพราะ raster โหลดผ่าน `file://` ได้อยู่แล้ว

**สิ่งที่เราทำ:** `tools/build_map_inline.js` อ่าน `load-map-layers.js` + SVG สองไฟล์ของคุณ
แล้วห่อเป็นสคริปต์ธรรมดาก้อนเดียว **316 KB** (ข้อความล้วน ไม่ฝัง PNG)
ตัวสร้างแก้ต้นฉบับของคุณ **สามจุด และทุกจุดมี assert** — คุณเปลี่ยนโครงเมื่อไหร่มันตายเสียงดังทันที:

| จุด | จาก | เป็น | ทำไม |
|---|---|---|---|
| 1 | `export async function loadMapLayers` | `async function loadMapLayers` | `export` ใช้ในสคริปต์ธรรมดาไม่ได้ |
| 2 | `new URL('./',import.meta.url)` | `new URL('./',document.baseURI)` | `import.meta` เป็น **syntax error** ตั้งแต่ตอน parse |
| 3 | `await fetch(url)` | บังด้วย `const fetch` ใน IIFE เดียวกัน | อ่านข้อความจากตัวแปรแทนออกเน็ตเวิร์ก |

**ไม่ได้ขอให้คุณเปลี่ยนอะไร** — ทางที่คุณทำถูกแล้วสำหรับ http และเราไม่ได้แตะเส้นทางนั้นเลย
แค่บอกให้รู้ว่ามีตัวแปลงนั่งอยู่ปลายทาง ถ้าจะเปลี่ยนสามบรรทัดนั้น **ช่วยบอกล่วงหน้า**

> ถ้าอยากช่วยให้ง่ายขึ้นอีก: ส่ง `load-map-layers.js` มาในรูปที่เป็น **classic script ได้ด้วย**
> (เช่น UMD หรือแยกไฟล์ `.classic.js`) แล้วเราจะเลิกแปลงเลย — แต่ **ไม่จำเป็น**

| `data/plate_water.js` (ของเดิม) | 89.9% | 84.7% |
| `delivery/water.svg` (ของคุณ) | **90.4%** | **84.2%** |

**สรุป: เท่ากันภายในความคลาดเคลื่อน** — ดีขึ้น 0.5 จุดด้านหนึ่ง แย่ลง 0.5 จุดอีกด้านหนึ่ง

★ **แต่สิ่งที่ของคุณดีกว่าจริงคือคนละเรื่องกับความแม่น และมันสำคัญกว่าที่คุณอาจคิด:**

1. **เป็นเวกเตอร์ที่มี id รายสาย** — 95 reach · 9 ทะเลสาบ · 4 ผืนทะเล
   ของเดิมเป็นวงรูปปิดล้วน ๆ ไม่มีชื่อ ไม่มีทาง "แก้แม่น้ำสายนี้สายเดียว"
2. **มี topology ที่ตรวจได้** — `water-verification.json` ยืนยัน endpoint ตรงกันเป๊ะ
   และ `unconnectedMouths: []` · ของเดิมไม่มีแนวคิดนี้เลย
   นี่คือสิ่งที่ตอบกติกา **"แม่น้ำต้องมีทางออก"** ที่เจ้าของตั้งไว้ (DECISIONS §14 เฟส 4.4)
   ซึ่งของเดิมทำได้แค่ *ตรวจ* ไม่เคย *รับประกัน*
3. **สเกลได้ไม่แตก** — ต่างจาก raster ของเดิม

**ข้อขอ:** อย่าไล่ precision 84% ให้เป็น 95% ด้วยการตัดเส้นทิ้ง — ตัวเลขที่หายไป 16% นั้น
ส่วนใหญ่คือ *ชายฝั่งคลาด ±1 ช่อง* กับ *ตัวอักษรฟ้าบนแผ่น* ซึ่ง `check_water.js` เขียนไว้เองว่า
**ตั้งใจให้ต่างและไม่ถือเป็นข้อผิดพลาด** · ถ้าจะปรับ ขอปรับที่ **recall** (หลุมที่ยังขาด) แทน

ของเรามีรายการหลุมใหญ่สุดให้แล้ว รันได้เลยจากรากโครงการ:

```bash
node tools/check_water.js --holes 20
```

หลุมใหญ่ที่สุดตอนนี้อยู่ที่ประมาณ **(668, 512)** ขนาด 53 ช่อง — ลองไล่จากตรงนั้นก่อน

## 6 · คำถามที่อยากได้คำตอบ

1. **`terrain.svg` ฝัง raster เป็น base64 ไว้ข้างใน — ตรวจแล้วว่าใช่ (1 ก้อน)**
   ขนาดตอนนี้ 3.8 MB · ถ้าขึ้นเป็น 2× ตาม §2 จะกลายเป็นราว **13–15 MB ในไฟล์เดียว**
   ซึ่งหนักเกินไปสำหรับหน้าที่โหลดครั้งเดียว (แอปจริงทั้งแอปตอนนี้เล็กกว่านั้นมาก)
   → **ขอเป็น PNG แยกไฟล์ + SVG ที่อ้างถึงมันด้วย `href`** แทนการฝัง base64
   ได้ทั้งแคชแยก โหลดขี้เกียจ และเปลี่ยนความละเอียดตามระยะซูมได้ในอนาคต
   (base64 ยังทำให้ไฟล์ใหญ่กว่าไบนารีจริงอีก ~33% ด้วย)
2. **ชั้นภูเขาตั้งใจให้อยู่ใต้หรือเหนือหมึกของแผ่นเดิม?** ต้นแบบใช้ `mix-blend-mode:multiply`
   กับแผ่นต้นฉบับ แต่ในแอปจริงตอนนี้ **แผ่นกลางคืนเป็นค่าเริ่มต้น** และเราวาดชั้นเขต/น้ำ/กำแพง
   ของเราเองทับอยู่แล้ว — ลำดับชั้นที่คุณคาดหวังคืออะไร
3. **ยังจะทำ terrain ให้ครบทั้งประเทศไหม หรือหยุดที่กวานจง–ฉินหลิ่ง–ฮั่นจง?**
   ตอนนี้ทั้งประเทศมีแต่น้ำ ภูเขามีเฉพาะย่านกลาง — ถ้าทำต่อ ผมอยากรู้ลำดับพื้นที่ล่วงหน้า
   จะได้วางแผนว่าจะเปิดใช้ทีละภาคหรือรอทีเดียว
4. **Avatar: ตกลงจะใช้ภาพเต็มตัว หรือครอปใบหน้า?** ต้นแบบทดลองไว้ทั้งสอง
   ฝั่งผมต้องรู้ก่อนวางโครง เพราะถ้าเป็นใบหน้า **ควรส่งไฟล์ใบหน้าแยกมาเลย**
   การครอปด้วย CSS จากภาพเต็มตัว 1254² จะโหลดของที่ไม่ได้ใช้ 80 ไฟล์
5. **พื้นหลัง avatar — เรื่องนี้พวกคุณแก้ไปแล้ว แค่ยืนยันให้ตรงกัน**
   ผมตรวจไฟล์แล้ว: `approved/liubei-alpha.png` เป็น **RGBA จริง** มุมทั้งสี่ alpha = 0
   โปร่งใสสนิท 72.3% · กึ่งโปร่งแค่ 0.5% (ขอบสะอาด) · ส่วน `approved/liubei.png` เป็น RGB ไม่มี alpha
   → **ขอให้ `-alpha` เป็นมาตรฐานของทั้งชุด 80 ตัว** เพราะพื้นหลังแอปจริงเป็นสีเข้ม

## 7 · สคริปต์วัดซ้ำ — รันได้เลย

ทั้งสองอันรันในคอนโซลของเบราว์เซอร์ที่เปิดหน้าไหนก็ได้ของโครงการ
(ต้องเสิร์ฟผ่าน http ไม่ใช่ `file://` ไม่งั้น canvas อ่านพิกเซลไม่ได้)

**ก · ภูเขาลงทะเบียนกับแผ่นหรือยัง** — ค่าที่ต้องการคือ ≥ 5×

```js
const load=(src,w,h)=>new Promise(r=>{const im=new Image();im.onload=()=>{
  const c=document.createElement('canvas');c.width=w||im.naturalWidth;c.height=h||im.naturalHeight;
  const x=c.getContext('2d',{willReadFrequently:true});x.drawImage(im,0,0,c.width,c.height);
  r({ctx:x});};im.src=src;});
const plate=await load('/assets/map.jpg'), terr=await load('/prototypes/codex-2026-09-06/delivery/terrain.svg',1650,1950);
const pd=plate.ctx.getImageData(0,0,1650,1950).data, td=terr.ctx.getImageData(0,0,1650,1950).data;
const g=new Float32Array(1650*1950);
for(let i=0;i<g.length;i++) g[i]=(td[i*4]+td[i*4+1]+td[i*4+2])/3;
const rough=(x,y)=>{let s=0,s2=0,n=0;for(let dy=-4;dy<=4;dy+=2)for(let dx=-4;dx<=4;dx+=2){
  const yy=y+dy,xx=x+dx;if(yy<0||yy>=1950||xx<0||xx>=1650)continue;
  const v=g[yy*1650+xx];s+=v;s2+=v*v;n++;}return Math.sqrt(Math.max(0,s2/n-(s/n)**2));};
let mS=0,mN=0,pS=0,pN=0;
for(let y=6;y<1944;y+=3)for(let x=6;x<1644;x+=3){
  const i=(y*1650+x)*4,R=pd[i],G=pd[i+1],B=pd[i+2],v=(R+G+B)/3;
  const isM=(G>R+14&&G>B+14&&v<180), isPaper=(v>200&&Math.abs(R-G)<30&&Math.abs(G-B)<40);
  if(!isM&&!isPaper)continue; const r=rough(x,y);
  if(isM){mS+=r;mN++;}else{pS+=r;pN++;}}
console.log('อัตราส่วนความขรุขระ ภูเขา/ที่ราบ =', ((mS/mN)/(pS/pN)).toFixed(2)+'x');
```
