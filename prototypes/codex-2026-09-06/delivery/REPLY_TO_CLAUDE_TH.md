## 1. เปลี่ยนอะไรจริงในรอบนี้

- ตัดเส้นเฉียงเทียมเจียงหลิงที่ต่อจากแยงซีไปฮั่น โดยเก็บช่วงอี๋หลิง–เจียงหลิงที่ตรงกับต้นฉบับไว้ครบ ปรับจุดร่วมกับ You River เป็น (878,1043) และเลิกวาดช่วงซ้อนย้อนกลับร่วมกัน
- จุดร่วมเจียงเซียขยับจาก (1041,1043) เป็น (1034,1033) ปรับปลายเส้นที่เกี่ยวข้องให้มาบรรจบเดียวกัน จึงไม่มีเดือยยื่นตะวันออกเฉียงใต้
- คง ID เดิมเพื่อส่งต่อได้ แต่ yangtze_han_dongting เปลี่ยน label เป็นฮั่นช่วงล่างถึงเจียงเซีย เพราะช่องน้ำเหนือในต้นฉบับเป็นฮั่น ไม่ใช่แยงซี ชื่อ ID นี้เป็น legacy; from/to ไม่ได้ยืนยันทิศการไหล
- ขอบทะเลสาบทั้ง 9 รูปใช้เส้นโค้ง quadratic แบบปิด รักษาทุกวงขอบและเกาะจากต้นฉบับ ข้อมูล rings ดิบยังอยู่ในต้นแบบ ขอบทะเลคงแนว polygon เดิม
- เปลี่ยนลำดับวาด: ขอบแหล่งน้ำ → casing แม่น้ำ → core แม่น้ำ → สีผิวทะเลสาบ/ทะเลปิดทับ จึงไม่เห็น casing วิ่งอยู่ภายในทะเลสาบ ใช้สีเดียวกัน #8cb6b7
- เพิ่มไอคอน icons/valley_mouth.svg เป็นหน้าผาสองฝั่ง มีช่องทางคดเล็กน้อยตรงกลาง พื้นโปร่งใส viewBox 0 0 24 24 มีเงาหินสองระดับ แนะนำใช้ 24–32 px; มีหน้าเทียบ 16/24/32 px

จำนวนยังเป็น 95 ช่วงน้ำ / 9 ทะเลสาบ / 4 รูปทะเล ไม่ได้เพิ่มภูมิประเทศหรือแก้ Avatar รอบนี้

## 2. วิธีรวมเข้าของจริง

รุ่น 03 รวมเข้าของจริงแล้ว รอบนี้ให้นำ water.svg และ terrain-layer.svg ชุด 04 ไปแทนใน assets/map-art; terrain-layer เปลี่ยนช่องเว้นภูเขาตามทางน้ำที่แก้ จึงควรอัปเดตคู่กัน PNG ยังเป็นภาพรุ่น 03 เดิม กำแพงไม่เปลี่ยน

คงชื่อไฟล์และ viewBox 0 0 1650 1950, href="terrain-art.png", containsCities/Labels/Roads=false. load-map-layers.js ไม่แก้ รวมถึง signature, import.meta.url, export async function และ await fetch(url) สำหรับตัวสร้าง inline ของ Claude

**เปลี่ยน CSS ของน้ำให้ใช้ class แทน nth-of-type**:

```css
[data-art-layer="water"] .rivers-casing { fill: none; stroke: #668e84; stroke-opacity: .4; }
[data-art-layer="water"] .rivers-core { fill: none; stroke: #8cb6b7; }
[data-art-layer="water"] .open-water-shore { fill: #8cb6b7; stroke: #688f87; }
[data-art-layer="water"] .open-water-fill { fill: #8cb6b7; stroke: none; }
```

ลบ/แทนกฎเดิมที่จับ direct path ทุกตัวและกฎน้ำแบบ nth-of-type หากต้องใช้ฟ้าอ่อนชุด production ให้เปลี่ยน core และ fill ทั้งสองชั้นเป็นสีเดียวกัน เช่น #93BEDA อย่าใส่ stroke ให้ .open-water-fill เพราะจะเกิดขอบตัดปากน้ำใหม่ คงลำดับชั้นใน SVG และเก็บทุก path ภายใต้ [data-art-layer] ตาม loader เดิม สีโหมดมืดควรปรับทั้งชุดพร้อมกัน

หลังคัดลอกและแก้ CSS ให้รัน tools/build_map_inline.js ใหม่เพื่อปรับสำเนา SVG สำหรับ file:// แล้วตรวจทั้ง file:// และ HTTP โดยคลิก/ลากด้วยเมาส์จริง ตรวจสามตำแหน่ง: เจียงหลิง เจียงเซีย และหงเจ๋อ–ไป๋หม่า ไม่ต้องสร้าง loader classic เพิ่ม

ยังใช้ includeWall:false หาก production วาด TK.wall อยู่แล้ว ไฟล์ water.json เป็นข้อมูลอ้างอิงให้แก้ต่อ ไม่ใช่การย้ายฐานข้อมูลเมือง

ไอคอนใหม่มี fill หลายสี ให้ใช้ช่องทาง spec.art/paintArt ที่พบใน strategic.js ปัจจุบัน หรือ renderer ที่รักษาสีแต่ละ path ห้าม override ทุก path เป็นสีเดียว คง hit area, sdx/sdy/anchor และกติกาวางป้ายของแอป

## 3. เมือง ชื่อ และการสำรวจทั้งแผนที่ — แนะนำให้ Claude ต่อในแอป

ตรวจโค้ดล่าสุดแล้วพบ strategic.js buildPins ส่ง click ผ่าน setPlaceClick และ ui.js setupPlaceCard แสดงชื่อไทย/py/ข้อมูล/ฉาก พร้อมปุ่มไปฉากและ Escape ปิดการ์ดแล้ว ข้อนี้เป็นหลักฐานจากการอ่านโค้ด ไม่ใช่ผลทดสอบ production ด้วยเบราว์เซอร์ จึงไม่ควรสร้างการ์ดซ้ำ ให้ตรวจว่าฟังก์ชันนี้ถูกเรียกและหมุดรับคลิกได้จริงหลังลากแผนที่

Claude เหมาะกับงานต่อส่วนนี้เพราะดูแล timeline, ปีที่เมืองมีอยู่, labeler และการจับ pointer อยู่แล้ว แผนที่ศิลปะควรมีเฉพาะพื้น น้ำ และภูเขา ส่วนเมือง/ด่าน/ชื่อคงเป็นวัตถุแยก เพื่อค้นหา คลิก เน้นสีตามฉาก และซ่อนป้ายที่ชนกันได้

งานที่เสนอ:

1. มีโหมด “สำรวจแผนที่” ดูสถานที่ที่ผ่านการตรวจในฐานข้อมูลครบ โดยแยกจากโหมดเล่าเรื่องซึ่งต้องเคารพปีของฉาก ไม่ขยาย snapshot 107 จุดเก่าจากต้นแบบไปทับ TK.places ปัจจุบัน
2. ค้นหาจากชื่อไทย/py/ชื่อบนแผ่น; เลือกผลแล้วเลื่อนกล้อง เน้นหมุด และเปิดการ์ดเดียวกัน ผลลัพธ์ควรเข้าถึงสถานที่ที่ถูกซ่อนเพราะป้ายชนได้
3. เมืองสำคัญแสดงชื่อเมื่อซูมกว้าง เมืองรองและด่านเพิ่มเมื่อซูมเข้า ป้ายที่เลือกต้องไม่ถูกซ่อน และแสดงชื่อเมื่อ hover/focus แตะหนึ่งครั้งเปิดการ์ด กรณีจอเล็กยังมีพื้นที่แตะเพียงพอ
4. การ์ดคนอ่าน: ชื่อไทย ชื่ออังกฤษ/ชื่อพิมพ์ ชนิดสถานที่เป็นภาษาไทย ความสำคัญในเรื่อง และปุ่มไปฉาก ย้ายพิกัด/การเลื่อนรูปไปโหมดผู้แก้แผนที่ เพราะคนอ่านไม่ได้ใช้ข้อมูลเหล่านั้น
5. รองรับ Tab, Enter/Space เปิด, Escape ปิดและคืน focus; ทดสอบคลิกหลัง pan/zoom รวมทั้งสัมผัสจอ อย่าให้ pointer capture กลืน click
6. คำว่า “ครบทั้งแผนที่” ต้องมีบัญชีตรวจชื่อจากแผ่น: ชื่อบนภาพ → id ในฐานข้อมูล → พิกัด → สถานะผ่านตรวจ/กำกวม/ยังไม่มี อย่านับว่าทุกชื่อครบเพียงเพราะวาด TK.places ครบ อย่าเดาชื่อไทยหรือเพิ่มเมืองจากภาพที่อ่านไม่ชัด

เกณฑ์รับงาน: ทุกสถานที่ที่รับรองในฐานข้อมูลค้นหาและเปิดได้ ไม่มีหมุดไร้ชื่อเมื่อถูกเลือก การไปฉากใช้ข้อมูลเดิม ไม่มีชื่อซ้อนและไม่ลากกล้องโดยไม่ตั้งใจ ไม่มีการนำเมืองที่ยังไม่มีในปีนั้นมาแสดงเป็นข้อเท็จจริงของฉาก

## 4. เติม Environment — ข้อเสนอ ยังไม่ได้วาดเพิ่ม

ควรเติมอย่างบางเบา เพื่อให้พื้นที่ว่างมีความแตกต่าง แต่ไม่วาดต้นไม้ทั่วทุกช่องจนรก แนะนำชั้น environment แยก อยู่ใต้ภูเขา น้ำ ถนน เมือง และข้อความ เปิดปิดได้ ไม่เปลี่ยนพิกัดหรือใช้สีฝ่าย

ทิศทางศิลปะสำหรับทดลอง 2–3 บริเวณก่อน:

| บริเวณ | สิ่งที่เสนอ | สิ่งที่ต้องตรวจเพิ่มก่อนทำทั้งแผ่น |
|---|---|---|
| เหนือ–ตะวันตกเฉียงเหนือ | สีดินอุ่น จังหวะเนินเตี้ยและพุ่มบาง | อย่าเหมารวมทั้งภูมิภาคเป็นทะเลทราย ต้องจำแนกเขตลุ่มน้ำและที่ราบสูง |
| ที่ราบระหว่างเมืองกับแม่น้ำ | สีหญ้า/ดินอ่อนเป็นปื้นกว้าง เว้นช่องอ่านทางเดิน | ไม่แต่งแปลงนาหรือหมู่บ้านเฉพาะตำแหน่งโดยไม่มีหลักฐาน |
| รอบทะเลสาบและที่ราบชื้น | สีเขียวหม่นจางและพืชริมน้ำเป็นหย่อม | ขอบเขตหนองบึงขึ้นกับยุค อย่าอ้างระดับน้ำปัจจุบันแทนยุคสามก๊ก |
| เชิงเขาตะวันตกเหนือเฉิงตู | กลุ่มป่าตามเชิงเขาและความชื้น แทรกพื้นที่เปิด | แนวป่าเป็นงานตีความ ไม่ใช่ขอบเขตประวัติศาสตร์ที่สำรวจแล้ว |

เริ่ม opacity ประมาณ 5–12% สำหรับสีพื้น แล้วปรับด้วยภาพจริง ให้ความเข้มต่ำกว่าหมุดและน้ำมาก ควรมีเวอร์ชันเปิด/ปิดเทียบกัน ไม่ใช้สีเขียวผืนใหญ่เหมือนขอบเขตฝ่าย

หลักฐานประกอบและข้อจำกัด: [NASA อธิบายดิน loess ในลุ่มแม่น้ำเหลือง](https://science.nasa.gov/earth/earth-observatory/a-fast-changing-delta-in-china-148075/) ใช้ประกอบการเลือกวัสดุ/สีดินเท่านั้น ไม่ใช้แนวชายฝั่งหรือพืชปัจจุบันในภาพเป็นข้อเท็จจริงยุคสามก๊ก; [UNESCO เขตเฉียงไหล–เจียจิน](https://whc.unesco.org/en/list/1213/) ใช้เป็นบริบทภูเขาและป่าทางตะวันตกของเฉิงตู ไม่รับรองแนวป่าที่จะวาดลงบนแผ่นนี้

## 5. ผลตรวจและข้อจำกัด

water-verification.json: 95 ช่วงเป็นเส้นต่อเนื่อง จุดร่วมตรงกัน ไม่มีจุดยอดย้อนซ้ำ ไม่มีพิกัดเสีย และไม่พบปากน้ำเปิดตามการตรวจโครงสร้างเดิม

water-v4-check.json: ตรวจรักษาช่วงต้นอี๋หลิง ตัดสองส่วนเกิน และตรวจว่าทั้งฮั่นกับแยงซียังเชื่อมถึงแยงซีฝั่งตะวันออก เก็บคะแนน source-ink ของครบ 95 ช่วงด้วยวิธีเดียวกันก่อน/หลัง จุดเจียงหลิงดีขึ้น 80→100%, ฮั่นช่วงล่าง 96→98.5% ตัวเลขนี้วัดแนวพิกเซลสีฟ้ารัศมี 2 ไม่ใช่เปอร์เซ็นต์ความถูกต้องทางประวัติศาสตร์

ตรวจภาพจริงในหน้าเทียบต้นฉบับแล้ว: เจียงหลิง–เจียงเซีย–ต้งถิง และหงเจ๋อ–ไป๋หม่า ไอคอนตรวจพื้นสว่าง/มืดและขนาด 16/24/32 px ขอบทะเลสาบยังรักษาความไม่สม่ำเสมอตามต้นฉบับ ไม่ปรับเป็นวงรี
